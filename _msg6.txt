docs: 两份上手文档（给人 / 给 agent）

仓库里之前只有"为什么这么设计"（ARCHITECTURE / DESIGN / 技术报告），
缺"我该按什么顺序动手"。两种读者需要的完全不是同一样东西，所以拆两份：

**docs/GETTING-STARTED.md —— 给人**
- 先说它是什么、**不是什么**（多设备同时写会分叉、没有实时同步、没有原生多模态）
- 三条路选一条：只看看 / 做一张自己的卡 / 备份搬家
- 第 0~6 步：装依赖（numpy + psutil，模型可选）→ 示例卡 → 改成自己的名字与人设
  → 开始说话（bridge.py ask/report 与 HTTP 两种）→ 接进 DSH（cardslot 插卡）
  → 看控制台 → 备份搬家（portable 四步 + install_runtime）
- 八个一定会踩的坑（端口占用、向量维度静默失效、GBK 乱码、真卡跑假时间、
  绕过台账删记忆、U 盘天天跑、MCP 插件、ffmpeg 路径）
- 一页速查表

**docs/FOR-AGENT.md —— 给接手改代码的 AI**
- 先分清"卡"与"通道"：不持有记忆，别编
- 五条铁律（副本才能跑假时间 / 删除只走 `_forget_row` / CORE 区走 API /
  不主动宣告遗忘 / 同时只能有一个写者）
- 接手顺序：health → status → selfcheck → health_audit
- 两个接口的形状（`/context` 收 `message`，`/report` 收 `user_message`+`reply`）
- 改代码要跑哪些测试、提交信息怎么写、哪些地方不该动
- 排查表（rollback / replaced / 语义检索失效 / database is locked / 控制台白屏）
- 还没做完的诚实清单

README 顶部加「从哪里开始」导航，指向这两份 + 三份设计文档。
