fix: 一次全面体检修七个真问题（默认池 / 假 dry-run / 名字主客颠倒 / chatter 漏知识）

体检四问：有没有 bug、有没有功能用不了、还有没有问题、是不是全在卡里。
查出三个一直在流血的老账 + 两个笔误级问题。

一、值守护值不进去：qq_guard 的 remember() 不传 pool
  /remember 默认 pool='short'（32 位）。对话已经过 decide() 判定"值得记住"，
  却被扔进注意力临时区，一溢出就被 _forget_row 删。
  实证：qq-group 写进卡 100 条、long 池 0 条；墓碑 373 条
  "短期池到期，海马判定没上榜" 大半是这条链。
  改：remember() 显式传 pool="long"。
  理由：要不要淡出该由 region 的衰减曲线管，不该由池子容量管。

二、--dry 名不副实：portable.py 先跑再拼参数
  r = _cardslot("inject") + (("--dry",) if args.dry else ())
  _cardslot() 会立刻 subprocess.run() 跑完再返回 CompletedProcess，
  往它上面加元组 TypeError —— 也就是"试运行"已经真落盘了才报错。
  改：先拼 argv 再调 _cardslot(*argv)，cmd_inject / cmd_eject 两处。

三、看门狗只证明端口 bind，不证明服务活着
  今早 NapCat 的 OneBot HTTP 适配器"端口在听、一个字节不回"：
  Test-NetConnection=True，但用原始 socket 发 GET /get_status 连续三次
  TimeoutError，守值从 07:48 起没收过消息。
  昨晚把判活从 6099 改到 6700 只解决了"看到错端口"，没解决"端口≠活着"。
  改：端口之后补一次真 HTTP（带 token 的 /get_status，超时 5 秒）。
  （脚本在 deploy/scripts/ 下，不在本仓，这里只记下结论。）

四、chatter 分区漏掉了"学到知识"这个例外
  用户原话是「今天聊明天忘光，除非重要/学到知识/强情绪」，
  但 _RE_CHATTER_KNOW 只管"关于人的稳定陈述"，没管"我刚学了什么"
  → 当天 18 条学习笔记被判成闲聊，半衰期 8.77 小时，隔天剩一成半。
  改：_RE_CHATTER_KNOW 追加学习/笔记/论文/实验/结论/出处/BV号/UP主 等，
  并加长度豁免 _LONG_CHATTER=60（判 chatter 是让它快点死，方向不安全，
  不确定时选让它活）。
  验：18/18 救回，16 条真闲聊一条没放走（第一版误加了"视频"，
  "我刚看了会儿视频"当场翻车，删掉）。
