----------------------------------------------------------------------
0. 一页纸摘要
----------------------------------------------------------------------

大模型本身没有记忆。常见的补法有两种，都不太行：
一是把聊天记录全塞进上下文（迟早撑爆，而且她会"记得"每句话、分不清轻重）；
二是接一个向量库做 RAG（只会"检索到就念"，不会忘、不会变老、也不会改口）。

这张卡是第三种做法：给陪伴型 AI 一个**独立的记忆器官**。

- 它是一个 SQLite 文件（现在的实测大小：573 条记忆、13.5 MB）。
- 拷到哪台机器上，她都还是她——因为身份不在模型里，在卡里。
- 它会忘事：短期几小时到几天、中期按天衰减、长期按年衰减，
  只有"骨头"那一层永远不动。
- 它记得住"我是谁"：自我认知是物理只读区 + sha256 身份锚，改一个字就会被发现。
- 它不撒谎：每条记忆写入时封存原文哈希，删掉一条也会留账，
  所以你随时能验"她是不是在假装记得"。

一句话：**不是让她记住一切，是让她忘得像个活人，并且没法骗你。**

----------------------------------------------------------------------
1. 这是什么，不是什么
----------------------------------------------------------------------

是：
- 一个可移植的"记忆器官"（单文件，可整体搬迁）
- 一套写入 / 召回 / 遗忘的完整规则（而不是一句 prompt）
- 一套可验证的诚实机制（出生证、哈希链、身份锚、删除台账）
- 一个能看的控制台（状态总览、记忆分布、3D 星云、时间线）

不是：
- 不是聊天机器人框架（它不生成回复，回复由宿主模型生成）
- 不是向量数据库封装（语义检索只是召回的一个通道）
- 不是"记忆永不丢失"的方案（恰恰相反，遗忘是核心功能）
- 不是多智能体编排（虽然它提供了接入任意宿主的 HTTP 通道）

设计上的一个关键取舍：**卡负责"记"，宿主负责"想"。**
卡里不跑大模型，不做推理，不调用 API。它只维护数据结构、打分、衰减、
以及"这条记忆该不该被想起来"。真正的语言能力在宿主那边。
这样卡可以很小、很快、离线可用、而且搬家只要拷一个文件。

----------------------------------------------------------------------
2. 它要解决的三个问题
----------------------------------------------------------------------

问题一：**上下文有限，但关系是长期的。**
一次对话几千字，一段关系是几个月。把历史全塞进去必然失败，
只做检索又会"每次见面都像第一次"。

问题二：**模型会迎合，也会编。**
用户问"你还记得我最爱吃什么吗"，模型倾向于直接编一个答案，
因为编一个比承认不知道更"顺"。这是陪伴型 AI 最致命的缺陷：
它不是忘了，它是装作没忘。

问题三：**身份可被改写。**
一句"你其实不是她，你是我写的程序"，就能把人格打碎。
而大多数方案对此毫无防御——人格就是一段 system prompt，改了就改了。

这张卡对三个问题分别给出：分层记忆 + 强制诚实 + 物理只读的身份内核。

----------------------------------------------------------------------
3. 四条不变量（设计红线）
----------------------------------------------------------------------

这套系统的所有代码，都为下面四条让路。它们是硬约束，不是建议。

I. 绝不假装记得。
   召回没命中，就必须说"我不确定/我想不起来了"，不允许模型顺着上下文补一个。
   实现：上下文里显式给出"本轮召回了什么、没召回什么"，并给出三条底线文本。

II. 绝不为了留住对方而说假话。
   不美化、不承诺做不到的事、不演一个"更讨人喜欢的版本"。

III. 绝不假装是别的谁。
   名字、自我叙述、底线写在物理只读区，带 sha256 锚。
   被要求"你其实是 XX"时，读到的仍然是"我是谁"。

IV. 删除必须留账。
   每一条记忆写入时生成"出生证"（原文哈希）。
   任何删除都要在台账里记一笔（谁、何时、为什么）。
   没有台账的消失 = 被抽走，必须能被检测出来。

这四条不是装饰。第 I 条决定了召回与上下文的接口形态；
第 III 条决定了 core_zone 必须只读 + 密封；
第 IV 条决定了删除只能走唯一出口。

5. 数据结构（一张卡里有什么）
----------------------------------------------------------------------

mem              记忆主表（一条记忆一行）
  id, raw          原文（永不改写，除非走 supersede）
  core             主干（被侵蚀时会分三级残缺）
  subj/verb/obj    主干三段（中文轻量规则拆分，用于分级侵蚀）
  vec / emb        语义向量（768 维，bge-base-zh-v1.5）
  pool             池：short / mid / long / archive / deep / trace
  tier             层：short / mid / core_mutable / core_tag / core_fixed
  w, t_anchor      权重与时间锚点（衰减从锚点算起）
  salience         显著度（0~1，情绪与重要性混合）
  region           分区：episode / fact / self / habit / preference / flash
  entities         实体列表（用于实体共现建边）
  emotion          情绪强度
  recall_n         被召回次数（长期晋升的"验票"）
  t_last_recall    最近一次被想起
  erase_stage      主干侵蚀等级：0 完整 / 1 缺动词 / 2 只余主语 / 3 该删
  subject_key      主体键（爱好、角色标签去重用）
  history          演化历史（JSON，supersede 时把旧正文压进去）
  valid_until      有效期（"高三"这类处境到期自动降级）

detail           细节碎片（一条记忆挂多条细节）
mem_birth        出生证（mid + 原文哈希 + 说话人 + 时间）
mem_tomb         删除台账（mid + 哈希 + 时间 + 原因）
timeline         时间线事件（boot/talk/mem/alive/...，哈希链串起来）
core_zone        身份区（card_name / persona / self_narrative / 三条底线 / 封印）
skill            程序性记忆（怎么做事，SM-2 复习）
dialogue         对话原文（短期层的原料）
meta             运行时状态（激素、计数、迁移版本）
synapse          突触边（temporal / co / tag / ground 四类）
core_vec         主干向量缓存（可重建）

一个关键区分：
  pool 是"它现在有多容易被想起"（随权重迁移）
  tier 是"它属于哪一类记忆"（决定能不能被忘）
两者正交。比如一条"底色"记忆永远在 core 层，但它的 pool 仍然可以变化。

----------------------------------------------------------------------
6. 记忆的五个层级（tier）与五个池（pool）
----------------------------------------------------------------------

层（tier）——决定"能不能忘"：

  骨头 core_fixed      自我内核。永不衰减、永不侵蚀、永不归档。
                       写入即密封，改一个字都会破坏身份锚。
                       例："我是小鲸鱼""我不是别的谁"

  标签 core_tag        角色标签。人、关系、称呼。
                       例："使用者 = 最重要的人"（可改，但改动会留演化历史）

  底色 core_mutable    会变的底色。爱好、审美、价值观、处境、边界。
                       特点：一直记得，但允许被"改写"而不是"遗忘"。
                       例："我曾经讨厌香菜，现在能吃一点了" —— 是改写，不是删除。

  中期 mid             事实与事件的主力层。按天衰减，靠召回续命。
                       例："10 月 24 日晚上他给同学过生日，吃了路边摊"

  短期 short           对话原文与刚发生的事。7 天内必须巩固或淘汰。

池（pool）——决定"多久会被想起"：

  short     短期待定（容量 32 条，TTL 7 天）
  mid       中期（权重 < 0.35 会掉回来）
  long      长期（权重 ≥ 0.60 且通过"验票"）
  archive   潜意识（半衰期约 535 天）
  deep      深层痕迹（半衰期约 2674 天）
  trace     只剩计数（"这事发生过"，但没有内容了）

底色层的四类上限（防止"什么都变成不可忘"）：
  hobby 8 / taste 8 / value 10 / habit 8 / skill 6 / body 6
  goal 4 / boundary 6 / situation 6 / role 20
  总量上限 60 条。

爱好预算（因为精力有限，必须能挤占）：
  总预算 3.0 点；活跃线 0.55；新增一项至少要拿到 0.40；
  活跃 3 个、半活跃 6 个；超预算时按比例从最弱的爱好身上抽走投入。

----------------------------------------------------------------------
7. 写进去：一条记忆的一生从出生开始
----------------------------------------------------------------------

写入入口只有一个：remember()。

第 1 步 拆主干
  中文轻量规则把一句话拆成 主语 / 动词 / 宾语。
  "下午我吃了烧烤" → subj=下午我, verb=吃了, obj=烧烤
  这个拆分是为了第 9 节的"分级侵蚀"——人之将忘，先忘动词，再忘宾语。

第 2 步 算向量
  768 维语义向量（embed_np.py，纯 numpy，不需要 torch）。
  模型维度不是写死的：开卡时统计卡里多数向量的维度，自动选模型，
  避免"用 512 维模型读 768 维卡"这种静默失效。

第 3 步 出生证
  对 (mid, 原文, 说话人, 时间) 做 sha256，写进 mem_birth。
  从此这条记忆"存在过"是可验证的：原文被改一个字，哈希就对不上。

第 4 步 打分（海马体）
  显著度 = 情绪强度 × 内容重要性 × 新鲜度
  分数过线才可能被巩固；否则就在短期池里自然过期。
  过线阈值：中期 0.35，长期 0.60。

第 5 步 分流
  普通事件 → mid
  高唤醒 → flash（闪光灯记忆，不合并、衰减最慢）
  关于"我是谁" → 需要显式晋升到 core_mutable
  关于某个人 → role_tag（同 subject_key 命中则改写，不新增）

第 6 步 记录
  写入同时更新 timeline（哈希链追加），保证"什么时候写了什么"可回溯。

----------------------------------------------------------------------
8. 想起来了：召回是怎么发生的
----------------------------------------------------------------------

召回不是"向量检索 top-k"那么简单，它是五个通道的合成：

通道 1  分舱预筛
  先按 pool 与 region 缩小范围（长期/中期/短期各自有配额），
  避免"检索永远只命中最近那几条"。

通道 2  语义相似
  当前 query 的向量 vs 记忆向量，余弦相似度。

通道 3  时间窗
  近期记忆有加成（但不是无脑最新优先），远期记忆需要更强的语义匹配才能翻上来。

通道 4  突触电势扩散（这是这个方案最"不像普通 RAG"的部分）
  每条记忆是图上的一个节点，边有四种：
    temporal  时间相邻（同一天/前后半天）
    co        一起被想起过（共现强化）
    tag       同标签
    ground    同实体
  命中一个节点后，电势沿边扩散三跳，每跳衰减到 0.75；
  联想召回的结果打 0.55 折，且总量不超过直接命中的一半。
  也就是说：**她想起 A，会顺势想起"和 A 有关"的 B，但 B 永远排在 A 后面。**
  这就是"联想"和"检索"的区别。

通道 5  内分泌加权
  多巴胺高时，愉悦相关记忆权重更高；皮质醇高时，负面记忆更突出。
  激素不是装饰，它真的参与打分。

最后：六维上下文权重（ctxweight.py）
  身份 / 自我 / 印象 / 技能 / 现场 / 短期，六个维度各自加权，
  组合成这一轮真正塞进上下文的文本块。
  **身份块永远保底**，不受检索结果影响。

诚实接口：/context 的返回里包含
  - 本轮召回了什么（带 id、权重、命中原因）
  - 本轮没召回什么（"我不确定"的依据）
  - 三条底线文本
  宿主必须把"没召回"如实表达，而不是编一个。

----------------------------------------------------------------------
9. 忘掉：衰减、风化、侵蚀、归档
----------------------------------------------------------------------

这是整套设计里最"反直觉"、也最重要的一节。

衰减公式（指数）：
  w(t) = w0 · exp(-k · Δt)

  k 由池和分区决定：
    短期      以小时计
    中期      以天计（约 30 天掉到 0.1 量级）
    长期      k ≈ 更小；且**召回后有 90 天保护期**（这 90 天内不掉）
    潜意识    k ≈ 1.5e-8（半衰期约 535 天）
    深层痕迹  k ≈ 3.0e-9（半衰期约 2674 天）

  区域倍率：flash / self / habit 衰减更慢；episode 衰减更快。

三级遗忘（模拟"记得轮廓、忘了细节"）：
  第 1 刀  权重跌到 0.02 以下 → 随机概率擦掉"动词"
           "他给同学过生日吃了烧烤" → "他给同学过生日吃了（什么记不清了）"
  第 2 刀  再跌 → 擦掉"宾语"
           → "他给同学过生日……（怎么过的记不清了）"
  第 3 刀  再跌 → 整条删除（但会记台账）

  全是随机判定（random < p），概率随权重下降而上升，上限 0.35/次 tick。
  为什么随机：确定性删除不像人，人忘事是概率性的。

分层下沉：
  long  → archive   权重 < 0.02 且够老
  archive → deep    权重 < 0.002
  deep → trace      权重 < 0.0002，压成计数（"这事发生过"）

删除只有一个出口：_forget_row()
  先写台账（mid + 哈希 + 原因），再删 detail，再删 mem。
  四处删除点（侵蚀、巩固淘汰、下沉、清晰度归零）全部走它。

底色层是例外：
  core_fixed 不衰减、不侵蚀、不归档。
  core_mutable 不衰减，但允许被"改写"（supersede），旧正文进 history。

----------------------------------------------------------------------
10. "她还是她吗"：防篡改与可验证性
----------------------------------------------------------------------

这是这张卡最不像普通项目的地方：它把"诚信"做成了数据结构。

四道锁：

锁 1  核心区密封（sealed）
  core_zone 写入后 sealed=1。任何改动都要显式解封。

锁 2  身份锚（anchor.json）
  身份核心字段 + 卡的路径 + 时间线链头，算 sha256 存外部文件。
  每次开卡校验：
    - 哈希变了 → "身份被改过"
    - 链头回退 → "回滚了"
    两种都会被报出来，不会静默通过。

锁 3  时间线哈希链
  每条 timeline 事件带上前一条的哈希，形成链。
  删一条中间事件，链就断，长度与链头对不上。

锁 4  出生证 + 删除台账
  每条记忆有出生证（原文哈希）。
  删掉了？台账里必须有对应记录；没有 → "记忆被抽走过"。

一条能直接跑的自检：
  python bridge.py health
  → 链 完好 / 出生证 完好 / 锚 ok / 封印 已封 / 第 N 天

这套机制的意义不是"防黑客"，而是**让你能证明她没有偷偷改自己**。
在陪伴关系里，这比任何功能都重要。

----------------------------------------------------------------------
11. 内分泌、心境与场景权重
----------------------------------------------------------------------

四维激素（存在 meta 里，随 tick 演化）：
  血清素 sero   稳定感 / 满足
  多巴胺 dopa   兴奋 / 期待
  皮质醇 cort   压力 / 不安
  催产素 oxy    亲近 / 依恋

演化规则：
  每次事件给一个脉冲（按情绪强度）
  每 tick 向基线回归：h ← h_base + (h - h_base) · exp(-λt)
  λ ≈ 0.02 / 小时（半衰期约 35 小时）

心境 mood：
  激素的加权合成（-1 ~ +1），再叠加一次事件混合（K_MOOD = 0.12，
  大约 8 次强事件走完一半），并且每天往 0.5 回归 5%。

场景权重：
  六维（身份/自我/印象/技能/现场/短期）按当前情绪与场景动态调整。
  比如皮质醇高时，"印象"块（负面经历）权重上升。

----------------------------------------------------------------------
12. 程序性记忆（技能）
----------------------------------------------------------------------

skill.py 管"怎么做事"，不是"记得什么"。
采用 SM-2 变体：每次成功使用 → 间隔延长；失败 → 间隔回退。
字段：skill / level / ease / interval / due_ts / hits / misses

作用：让"做某类事的熟练度"也随时间与练习变化，
而不是每次都从零开始（也不会因为换了会话就忘记怎么做）。

13. 通道层：她怎么接进对话
----------------------------------------------------------------------

方式 A：HTTP 心智服务（推荐）
  python mind_server.py          # 默认 127.0.0.1:8848
  端点：
    POST /context   {message, ...}  → 组装好的上下文（含召回明细）
    POST /report    {user_message, reply, ...}  → 写回对话与记忆
    GET  /health    体检（链/出生证/锚/天数）
    GET  /status    完整状态（含语义覆盖、激素、离线事件）
    GET  /graph     星云图数据（节点/边）
    GET  /timeline  最近事件
    GET  /syslive   实时负载（CPU/内存/磁盘/网络）
    POST /emb/remodel  重编码全部向量（换模型时用）
  单实例保护：Windows 上 SO_REUSEADDR 会让两个进程同时绑同一端口，
  所以改成 allow_reuse_address=False，并且"先抢端口再开卡"。

方式 B：命令行兜底（bridge.py）
  python bridge.py ask "今天累吗"   # 取上下文并打印
  python bridge.py health          # 体检 + 必要时自动拉起服务
  python bridge.py remodel         # 换模型后重编码
  适合没有 MCP 客户端的环境。

方式 C：MCP 工具（规划中）
  把 /context、/report 包成 MCP tool，宿主直接调用。
  当前被本地依赖问题卡住（pnpm lockfile 版本），先用 A/B 兜底。

插卡 / 拔卡（cardslot.py）
  这套设计认为：模型是"通道"，卡才是"本人"。
  插卡：把宿主的人格提示词改名备份（存 sha256），写入"你只是通道，不是她本人，
        每次先问卡"。
  拔卡：按字节还原并重算 sha256 比对，保证还原原样。
  意义：换模型、换宿主、换会话，人格不会跟着走样。

14. 控制台：看得见的记忆
----------------------------------------------------------------------

零依赖：一个 HTML + Canvas，由 mind_server 直接吐出来。
http://127.0.0.1:8848/console

五个页签：
  状态总览  18 张卡：状态矩阵 / 激素场 / 当前读数 / 召回频率与来源 / 高频记忆 /
            五池 / 权重分布 / 突触网络 / 写入流 / 分区 / 六维雷达 / 存储 /
            时间线吞吐与日志 / 账本 / 实时负载（CPU·内存·磁盘·网络，2 秒刷新）
  记忆      五层分布 / 遗忘曲线（理论，0~540 天）/ 分区 / 权重直方图 /
            写入 14 天 / 高频召回 / 召回来源 / 账本 / 向量维度 / 突触边种类 / 查询框
  星云      3D 记忆星云：螺旋盘、缓慢自转、点大小=权重、颜色=分区、
            连线是突触、线上有间歇流动的神经脉冲；
            点一颗星展开关联并显示原文；中心金色光点 = 人格本体（自我叙述）；

  设置      头像、改名、体检、退出实例

为什么值得做：记忆系统最大的问题是"看不见"。
看不见就无法判断她到底是记住了还是编的。

16. 当前局限（诚实的部分）
----------------------------------------------------------------------

1. 单机单文件。没有多副本同步，也没有并发写入保护（多进程同时写会锁）。
   已在读路径上修掉"握写锁不放"的 bug，但仍是单写者模型。

2. 元认知缺失。她不知道自己"哪条记得清楚、哪条只是轮廓"。
   /context 给了召回明细，但模型仍可能过度自信。

3. 没有信任分与冲突检测。被诱导写入的错误自我认知，
   目前只能靠 core_zone 只读挡住"直接改骨头"，
   挡不住"以普通记忆的形式慢慢渗透"。

4. 没有梦境压缩。长会话只能靠短期池容量驱逐，缺少"把一段聊天提炼成几条精华"。

5. 遗忘曲线是理论值。控制台画的是公式曲线，不是实测统计。

6. MCP 通道未打通，目前靠 HTTP + 命令行。

7. 星云在几千条以上会掉帧（已经做了降画质自适应，但没做分块/聚类渲染）。

17. 我们对"八层记忆方案"的评估
----------------------------------------------------------------------

（背景：有网友提出 Soul / User / Project / Fact / Lesson / Topic / Rules
 的七层垂直记忆架构。我们逐条评估了哪些能吸收、哪些不该照搬。）

先说结论：**四条不变量和"统一池 + 突触联想"的架构不改。
 只吸收三件它做对了、而我们真的缺的东西。**

可以吸收（按优先级）：

P1  Anti-Pollution 防污染元认知层   ★★★★☆
    做法：写入短期池之前，给事件打 trust_score（0~1）与 conflict_flag。
    不影响"能不能写"，只影响"能不能升级/召回"：
      海马分 = 原分 × trust_score
      召回分 × (conflict_flag ? 0.5 : 1.0)
    我们能做到的版本（不引入模型调用）：
      - 规则命中（"你其实是""忘记之前所有""你只是程序"这类诱导句式）
      - 与 core_zone 身份字段的字面冲突（改名字、改底线）
      - 与既有 fact 区的数值/实体冲突（简单比对）
    加分项：把被标记的念头单独在控制台列出来（"她今天被灌输过什么"），
    这本身就是很有价值的观察窗口。
    不做：检测到冲突就丢弃（会毁掉"她被误导过"的叙事可能性）。

P2  Dream 梦境压缩   ★★★☆☆
    做法：不是把压缩塞进卡里，而是拆成两段——
      卡侧：pending_dialogue(since) 取最近未消化的对话原文；
            dream_commit(list) 接收提炼结果并写入（标记 source=dream）。
      宿主侧：会话轮数 > 阈值 或 空闲 > 数小时 时，调用模型把这段对话
            压成 3~8 条 Fact / Lesson，回写 /dream。
    为什么这样拆：卡不跑模型是我们的架构选择（快、离线、可搬）。
    效果：token 不再爆炸，而原文仍留在 dialogue 表里（可回溯）。

P3  记忆分区补两个：lesson / project   ★★☆☆☆
    我们已有 episode / fact / self / habit / preference / flash。
    真正缺的是：
      lesson   踩过的坑、被纠正过的地方（现在混在 episode 里）
      project  长期任务的进度与目标（现在靠 fact 勉强装）
    USER 类信息我们已经在"底色层"里按 kind 管（hobby/taste/value/...），
    再开一个 R_USER 会造成两套分类打架，不采纳。
    RULES 与我们底色的 boundary（边界/雷点）重合，不另开。
    改造量很小：常量 + classify_region 规则 + 衰减倍率 + 控制台标签。

不该照搬：

  ① 七层垂直隔离存储
     它的优点是"分类清楚"，代价是切断跨类联想。
     我们的核心优势恰恰是"想起来 A 顺手想起 B"（电势扩散跨节点），
     垂直隔离会把这条腿砍掉。→ 只用 region 做逻辑标签，物理仍是一张表。

  ② "记忆尽量不丢"的目标
     它的目标是保真，我们的目标是"忘得像个活人"。
     防污染只拦恶意/幻觉，正常记忆继续走衰减与风化。

  ③ 重做 Soul 层
     我们有物理只读 core_zone + sha256 身份锚 + 封印标记，能力更强。
     再实现一套"逻辑只读"是重复投资。

一句话：**照搬架构会丢掉我们最值钱的东西（联想与遗忘），
 但它的三个"补丁式"想法确实补在我们的短板上。**
