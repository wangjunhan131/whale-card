第 0 章　它是什么，不是什么
--------------------------------------------------------------------------------
【是什么】
  一份住在单个 SQLite 文件里的长期记忆 + 人格锚 + 情绪身体 + 动机天气。
  换机器时把这个文件拷走，插上就能接着说话 —— 记忆、性格、说话习惯都在里面。

【不是什么】（这几条是硬约束，也决定了下面所有设计）
  1. 不训练模型。没有任何 LoRA / 微调 / 权重文件。智商来自外面的模型，
     这里只负责「她记得什么、她此刻什么状态、她怎么开口」。
  2. 不做好感度分数。关系只用「分层」表达（陌生/认识/朋友/亲近/核心），
     不给感情记账 —— 记账会把陪伴变成积分任务。
  3. 不假装记得。检索不到就如实说没翻到，不允许用语言补全不存在的记忆。
  4. 遗忘是静默的。控制台里能看见权重在掉，但对话里绝不预告「我快忘了」。
  5. 不联网保存隐私。所有状态在本地一个库里，服务只绑 127.0.0.1。

2.1　记忆卡核心（MemoryCard）
--------------------------------------------------------------------------------
目的：一张卡 = 一个 SQLite 文件，所有状态都在里面，没有第二处。

数据表（主要）
  mem            记忆本体。39 列，核心是：raw(原文)/core(压成一句)/vec(字面向量)/
                 emb(语义向量)/pool(池)/region(分区)/w(权重)/t_anchor(时间锚)/
                 salience/access_count/recall_n/create_ts/last_active_ts/
                 trust/conflict/source/about_uid/about_layer/mtype/speaker/
                 superseded_by/valid_until/history
  detail         一句话拆成的片段（主谓宾），供精确检索
  core_zone      人格锚：self_name / card_name / 三条底线 / persona / self_narrative
  meta           键值配置（时钟、开关、身体参数、动机状态…）
  timeline       哈希链（见 2.5）
  mem_birth      记忆 → 时间线序号 的映射（mid, seq, ts, hash）
  mem_tomb       删除台账（谁、什么时候、为什么删）
  mem_del        已删 id 集合
  dialogue       对话流水（Dream 整理用）
  media / media_ref / media_tomb   媒体记忆（见 2.11）
  viscera_hist   身体与情绪的时序样本（控制台画曲线用）
  synapse        突触（记忆之间的边）  synapse_log  突触变更审计

四个池（pool）—— 是「注意力预算」，不是「寿命开关」
  short    正在想的事。容量 120 位。超过容量不是直接删，而是「降级到 medium」。
  medium   最近用得上但没在想的。降级时保一个权重地板，不会被清空。
  long     长期。进长期要满足条件（见 2.3 长期票据）。
  archive  潜意识。不参与实时检索，除非显式点名要翻。

六个分区（region）—— 决定「忘得多快」
  fact（事实）/ pref（偏好）/ self（自我）/ habit（习惯）/
  episode（经历）/ flash（闪光灯，强情绪事件）
  外加 4 个「短命区」：chatter（闲聊）/ play（娱乐）/ study（学习）/ work（工作）
  还有 lesson（教训）/ project（项目）两类，走 fact 系寿命。

对外接口（本地 HTTP，默认 127.0.0.1:8848）
  GET  /health            体检：条数、链、锚、天数、语义模型状态
  GET  /context?q=…       取这一轮该带的上下文（人话，不是 JSON）
  POST /report            一轮结束写两条（他说的话 + 我说的话）
  POST /remember          单独记一条（可指定 pool/region/source/about_uid）
  POST /forget            删除一条（写墓碑，不物理删）

降级行为
  语义模型缺失 → 自动退回字面向量检索（usable_ratio 会掉，但不会崩）。
  数据库被占 → 30 秒 busy_timeout；再不行返回 409，绝不静默丢写。


2.2　写入门（值不值得记）
--------------------------------------------------------------------------------
目的：**不是所有话都该进卡。** 卡里每天几百条群消息，全记下来等于没记。

判断顺序（先命中的先定，不往下走）
  1) 强情绪（怒、哭、崩、激动）           → flash，salience 0.9+
  2) 重要 / 学到知识 / 教训               → fact 或 episode
  3) 关于人的稳定陈述（我是谁、住哪、读哪） → fact
  4) 偏好（喜欢/讨厌什么）                → pref，**必须排在情绪判断之前**
  5) 其余闲聊                             → chatter（12 小时半衰期）

降噪（群聊专用）
  复读判定：与最近 20 条做 bigram Jaccard，≥0.82 视为复读，不记。
  最短长度 3 字；被 @ 时放行（那是叫到我）。
  私聊不走这道闸 —— 私聊的碎话恰恰是关系的质地。

去重
  同 raw 已在库中且分区不同 → 只更新旧条的时间与权重，不新增。
  历史导入里「同一件事说三遍」→ 检索侧再用 Jaccard 0.55 二次去重。

时间锚定（写入 / 渲染时做，不改原文）
  把「昨天 / 明天 / 前天 / 今晚」按**这条记忆自己的 create_ts** 换算成绝对日期。
  好处：三年后再读，「明天给你账号」不会变成「明天」。
  原则：raw 一字不动，只改用于显示/拼上下文的那一层。


2.3　遗忘引擎（权重衰减 + 巩固）
--------------------------------------------------------------------------------
目的：忘得**像人**，不是像缓存淘汰。

单个池的权重曲线
  w(t) = w0 · 0.5 ^ (Δt / 半衰期)

  半衰期（实测标定，不是拍的）
    S1（短期池前 3 天）   4.46 天
    S2（短期池第 4~7 天） 0.53 天
    中期池                29.71 天
    长期池                371.41 天
  story：短期池前 3 天忘得慢、第 4 天开始断崖 —— 对应「刚发生的事记得清，一周后就糊了」。

分区各自的曲线（V5.2）
  闲聊 chatter  12 小时
  娱乐 play     3 天
  学习 study    7 天
  工作 work     15 天
  实现：`effective_lambda()` 在 pool 的 λ 上叠加区域自己的 λ，
  再用 stage_factor 让区差穿过中期池：short 1.0 / medium 0.15 / long 0.012。

  **为什么要分这么细**：一句「今天吃了什么」和一条「今天学到的机制」价值不同，
  寿命就不该一样。用户的原始要求是「今天聊的明天忘光，除非重要/学到知识/强情绪」。

按「对谁」定闲聊寿命（不是好感度）
  chatter_lambda(person_layer) × CHATTER_PERSON_SCALE
    陌生 1.0 / 认识 0.6 / 朋友 2.2 / 亲近 6.0 / 核心 24.0
  换算成 1 天后剩余权重：0.150 / 0.042 / 0.422 / 0.729 / 0.924
  说明：这是把**已有的关系层**接进寿命，不是给「聊得开心就加分」。

负载拥挤系数 f（当天写得多 → 忘得快）
  load[区] = load · exp(−Δt/86400) + 1
  f = clamp(sqrt(load / REGION_DAY_BUDGET), 0.55, 2.2)
  REGION_DAY_BUDGET = {chatter 40, play 10, study 20, work 8}
  实测：正常日 f≈0.75~0.9（几乎不动）；爆日 f≈1.7。

长期票据（进 long 的条件）
  w ≥ 0.80 且被召回 ≥ 3 次；
  例外：flash（强情绪）/ self（关于她自己的）/ habit（习惯）/ salience ≥ 0.75 只需 1 次。
  保护期：进长期后 90 天内不参与淘汰。**先扣保护期，再乘分区倍率** ——
  顺序反了会把 90 天变成 300 天（这是修过的一个真 bug）。

半衰期的反面：召回加固
  每被成功召回一次：g = GAIN_ACCESS / (1 + ACCESS_DIMINISH · access_count) · room
    GAIN_ACCESS = 0.08　ACCESS_DIMINISH = 0.15　room = 1 − w
  同一件事重复记：g = GAIN_REPEAT · (1 − w)，GAIN_REPEAT = 0.10
  **一天最多加固一次**，且 w 有天花板。
  为什么：早期版本每次召回 +0.08、半衰期 4.46 天，
  结果「每天被召回两次」的条目被永久钉在 0.856 —— 越没用越容易被捞出、越捞越结实。

删除与遗忘的区别
  遗忘 = w 掉到阈值以下 → 写 mem_tomb（哪一条、什么时候、为什么、当时那句话）→ 逻辑删除。
  删除 = 用户明确要求 → 写 mem_tomb → 同样逻辑删除，raw 进墓碑，绝不物理抹。
  目的：能区分「她真的忘了」和「有人把记忆抽走了」。


2.4　检索引擎（像 / 清楚 / 久没提）
--------------------------------------------------------------------------------
目的：问一句话，翻出最该被想起的几条 —— 并且能解释为什么是这几条。

四因子打分（权重和为 1）
  score = 0.35 · 语义相似 + 0.30 · 字面覆盖 + 0.20 · 权重 + 0.10 · 新近
    SCORE_W = (0.35, 0.30, 0.20, 0.10)
  语义相似：句向量余弦（bge-base-zh-v1.5，768 维；缺模型时退字面）
  字面覆盖：IDF 加权的关键词覆盖率（低频词说了算：QQ、烧烤这种）
  权重：w（就是遗忘曲线里那个）
  新近：exp(−age_days / 14)
  权重本身有上限（W_CEIL_RECALL）：短期 0.95 / 中期 0.90 / 长期 0.95。
    上限不是为了「压分」，是为了不让一条记忆被反复召回钉死在 1.0：
    留一截余量，是承认公式没有上界、而「很结实了」和「算不出来」要分开。

乘性修正（依次相乘）
  × (0.85 + 0.30 · salience)      重要的更容易想起
  × f_endo(oxy)                   催产素高 → 羁绊记忆更容易翻出来；皮质醇高 → 回忆闭塞
  × trust 映射（trust<1 压到 0.5~1.0）   可疑来源的记忆压低
  × conflict 惩罚                  被判为「冲突/改写」的更低调

四个「预筛」（只收窄候选，不改分，收得过狠会自动放宽）
  时间窗：问「今天」就不翻三年前的（问「以前」则不限）
  分舱（pods）：先按语义聚成小簇，只在相关簇里找
  分区路由：问事实走 fact，问经历走 episode；命中不足 2 条就回退全库
  突触扩散：直接命中之后，沿 synapse 往外跳 2~3 跳，邻居以 0.55 折并入（排在直接命中之后）

统一时间线（V5.3.2）
  每条召回结果带 mem_birth.seq（哈希链上的真实序号），
  输出时**按 seq 排序**、行首挂短日期（`11-05｜…`）；
  被新说法取代的标「旧说法」。
  用处：两件事冲突时以链为准定先后；编号出来的事没有时间戳，天然对不上。

两个被实测否决的改动（留着开关，默认关）
  ① 情绪加权 `× (1 + 0.25·emotion)`：R@1 75% → 37.5%，EVID 100% → 0%
  ② 双时间尺度 recency `0.7·exp(-age/0.5d) + 0.3·exp(-age/14d)`：同样 37.5%
  根因：每天几百条群消息，任何「越近越加分」顶上来的都是刚聊完的废话。
  **问题在写入侧，不在检索公式。**（开关：WHALE_EMO_BOOST / WHALE_FRESH_STEP）


2.5　时间线引擎（可检测的篡改 + 定先后）
--------------------------------------------------------------------------------
目的：**能发现**「这张卡被改过」，以及给「谁先谁后」一个权威答案。
边界（别把话说满）：锚文件和卡在同一个盘、同一套权限下 ——
  能挡住的是「改了卡里的历史但忘了同步改锚」，
  挡不住的是「拿到整台机器的人把卡和锚一起重写」。
  所以准确说法是「可检测的部分篡改」，不是「不可篡改」。

结构
  每个事件占一行：seq（自增）、type、payload、self_hash、prev_hash、writer、ts
  self_hash = SHA256(上一条 self_hash + 本条内容 + seq)
  → 改任何一条历史，后面全断。

两种篡改的判据（anchor.py）
  rollback：链头 seq 比锚记的**少** → 被回滚过
  replaced：条数涨了但 seq 没前进 → 被替换过
  锚文件放在卡外，文件名 = SHA256(卡绝对路径)[:16]
  → 换盘即「没有锚」，所以搬家时 land 会按新路径重写锚名。

写入闸（多副本防分叉）
  每台机器一个 writer_id（~/.dsh/writer-id.txt）。
  /report 写入前比对链头 writer：不是本机 → 409 card_locked，整卡只读。
  带出门的副本打 RETIRED.json，插回来由「接回来」脚本清标记。

记忆 ↔ 序号绑定
  mem_birth(mid, seq, ts, hash)：每条记忆出生时那一条时间线的编号。
  这样「回忆」和「事件流」是同一套坐标，不会出现「记得有这回事但对不上哪天」。


2.6　人格锚（Identity / Anchor）
--------------------------------------------------------------------------------
目的：换电脑、换窗口、换模型，她还是她。

core_zone 里存什么
  self_name / card_name / 三条底线（原文，不许改写）
  persona（说话方式，会随相处慢慢演化）
  self_narrative（她怎么讲自己）
  seal：把以上内容与创建时间一起封存，读的时候校验一致。

三条底线（写进人格锚，每个引擎都要绕不过它）
  ① 绝不假装记得
  ② 绝不为留住他说假话
  ③ 绝不假装是别的谁

契约提醒
  一个常见 bug：seal 时 `DELETE FROM core_zone` 后只重建 6 个固定键，
  persona / self_narrative 被静默删掉 —— 修法是先抄出非固定键，重建后放回。


2.7　情绪第一层：心境（mood，慢，按天）
--------------------------------------------------------------------------------
目的：一个持续几天的底色。它不是每句话的情绪，是「这几天过得怎么样」。

模型
  mood 向基线回归：d = 1 − exp(−K_MOOD_HOME · days)，K_MOOD_HOME = 0.05
  （早期写成线性 min(1, k·days) 会在第 20 天精确归零，改用指数后不会「突然没情绪」）

对外只输出一个词：很好 / 还行 / 有点低落 / 不太好 —— 不输出数字。


2.8　情绪第二层：三维此刻（PAD）
--------------------------------------------------------------------------------
目的：此刻的「愉悦-唤醒-掌控」三轴读数，供控制台与语气微调用。

  P = (mood − 0.5) × 2
  A = ((0.6·dopa + 0.4·cort) − 0.32) × 3.2
  D = ((0.6·oxy + 0.4·(1 − cort)) − 0.62) × 3.2
  全部 clamp 到 [−1, 1]，再映射成八象限中文标签（平静/坐立不安/心花怒放…）

关键约束：**在身体基线处必须正好等于 0**。
  早期版本把 V3.7 的四激素直接喂进来，基线偏移被 ×3.2 放大，
  于是「平静」被显示成「坐立不安」。修法是把 24 激素按各自基线归一化后再算。

心境与三维故意不合并：心境是慢的（一天尺度），三维是此刻（一句话尺度）。


2.9　情绪第三层：身体（viscera，秒级）
--------------------------------------------------------------------------------
目的：**先有生理反应，再有情绪，最后才是回答。**
（用户原话：「有人说了一句让你不高兴的话，你应该是先有生理反应，
  然后导致你的情绪变化，然后你再根据你的情绪变化做出回答」）

24 种激素 + 自主神经 + 躯体体征
  激素：多巴胺/去甲/皮质醇/血清素/催产素/内啡肽/促性腺/褪黑素/GABA/乙酰胆碱/
        抗利尿/多巴胺前体/CCK/生长激素/催乳素/组胺/腺苷/犬尿氨酸/NPY/NPS/
        孤啡肽/脑啡肽/食欲素/睾酮
  自主神经：交感（瞬时兴奋）、副交感（瞬时镇静）
  躯体：心率 58~130、呼吸 10~30、体温 35.8~37.6、面色、肌肉张力

三条硬规矩
  ① **慢变量在单次刺激里只吃 40%** —— 一句话不该改掉三天的依恋
  ② 单轮增量按基线缩放：k_scale = clamp(base/30, 0.40, 2.20)，单轮限速 15% 基线，
     且无条件夹在 [0.35×base, 2.5×base]（否则会出现「某激素永远 0」或「顶到 100」）
  ③ 交感/副交感用**漏积分**：sym = clamp(sym × 0.45 + Δ)（累加会十几轮顶死）

衰减与调节
  每个变量各自半衰期（去甲 1.2h、组胺 2h、多巴胺 3h、皮质醇 20h、催产素 96h、促性腺 200h）
  六条负反馈（CCK 压多巴胺、GABA 压去甲、皮质醇广谱压制、孤啡肽过载抽离、腺苷累积疲惫、
  副交感延迟压交感）+ 四条正反馈 + 四组拮抗，每轮幅度都很小。

静息不静止
  没有事件时不做「一路回落到基线」（那会画出数学上的直线），
  而是往静息点拉 + 加小噪声：
    REST_SYMP 0.10、REST_PARA 0.10、σ_symp 0.065、σ_para 0.055、σ_hormone 0.030×base
  效果：心率在 73~79 之间自然起伏 —— 那不是「假抖动」，是静息时的呼吸性变异。

输出
  describe() 只说人话，最多三段，**永不出现数字**：
    「心跳快了一拍；呼吸变浅了；脸颊有一点点热」
  这层文字进上下文时放在【身体】格，位置在【此刻】之前 —— 顺序本身也是信息。


2.10　情绪第四层：预期误差（synapse_emotion / RPE）
--------------------------------------------------------------------------------
目的：情绪不是由「他说了什么」这种绝对量决定，而是由「比预期好还是差」决定。

七步链路
  ① 安全评估（威胁/越界/冷淡词表打 0~1）
  ② 价值打分 V_actual =
       0.50 + 0.30·夸奖 + 0.28·关心 + 0.14·分享 + 0.30·亲密·gate
            + 0.28·(投入度 − 0.5) − 0.30·冷淡 − 0.60·威胁 − 0.50·越界 − 0.12·忽视
  ③ 取预期（按事件类型的历史期望，TD 学习：expect += 0.16 · RPE）
  ④ RPE = V_actual − V_expected；情绪用放大版 RPE_eff = RPE × 1.75（学习用原始值）
  ⑤ 调质脉冲：pulse_k = (gain_pos_k 或 gain_neg_k) × RPE_eff × 敏感化 × 疲劳折损 × 内源情绪
  ⑥ 回落：M_k(t) = 基线 + (M_k(t−1) − 基线) · 0.5^(dt / 半衰期)
     半衰期（轮）：DA 1.6 / NE 2.2 / 5-HT 5.0 / CORT 8.0 / OT 16.0
  ⑦ 学习与漂移：基线 += 0.05·RPE + 0.035·(出厂值 − 基线)
     **最后那一项是强制回归** —— 没有它，皮质醇会只涨不落，30 轮后卡死。

三条时序硬规矩（都是踩过坑才加的）
  · **先衰减、再注入**。反过来，脉冲会在同一轮被吃掉三分之一。
  · safety 开门：gate = clip((safety − 0.35)/(0.75 − 0.35))；亲密项乘 (0.25 + 0.75·gate)
  · safety < 0.25 时自动追加「禁止任何暧昧试探」；/state 的数值永不进模型。

12 个中文标签：羞涩心动 / 心动悸动 / 轻快愉悦 / 安稳松弛 / 失落收敛 / 害怕回避 /
             忐忑不安 / 愧疚自责 / 酸涩在意 / 疲惫倦怠 / 抽离麻木 / 五味杂陈
  「五味杂陈」只在信号冲突时出现（比如多巴胺高同时皮质醇也高）。

下游联动（13 条，每轮一次，单轮封顶 ±0.5）
  多巴胺↑ → 多巴胺前体↑、催乳素↓、食欲素↑、CCK↓、组胺↓
  去甲↑   → 腺苷↑、NPY↑、组胺↑、GABA↓
  皮质醇↑ → 抗利尿↑、犬尿氨酸↑、脑啡肽↑、睾酮↓、食欲素↓
  催产素↑ → 催乳素↑、GABA↑（另有一条「暖意通道」0.18，在夸奖/安慰/调情/道歉时走）
  夜间    → 血清素↑ → 褪黑素↑
  这些都是教科书级别的方向，不是拟合出来的权重。


2.11　动机引擎（motiv，V5.3.2）——「只反应不起念」的那个缺口
--------------------------------------------------------------------------------
目的：不是被叫才动，而是自己有个「内在天气」：今天更好奇还是更想黏人。
      但**动机不等于行动** —— 想做的事要过四道门。

七条驱力（名字: 基线 / 半衰期）
  好奇 curiosity .52/8h　依恋 attachment .55/5h　胜任 competence .42/10h
  好玩 play .34/6h　关心 care .48/7h　休息 rest .30/4h　秩序 order .38/12h

六类欲望（主驱力 / 成本 / 风险）
  主动开口 reach_out(.35,.45)　自己学习 learn(.55,.10)　整理 tidy(.30,.05)
  玩一会儿 play(.40,.15)　关心一下 care_check(.25,.35)　歇会儿 rest(.10,0)

仲裁的四道门（硬否决，并写清理由）
  · 上课时段（07:20–12:25 / 14:40–22:25）不打扰
  · 安静时段不打扰
  · 距上次主动开口 < 1 小时不做
  · 当天主动开口额度（默认 4 次）用完不做
  · 学习不能在正在聊天时抽身（idle < 10 分钟不做，日额度 12 次）
  · 风险 ≥ 0.7 一律不自动做

两条设计纪律（很重要）
  ① **bump 只降不升**：做了这件事，对应驱力下降；任何驱力都不许被抬高
     —— 否则又变成了「好感度积分」。
  ② 候选照生、仲裁否决：想就是想了，哪怕现在不能做，
     日志里也要留下「我想了但没做」这一笔。这样事后能解释自己。

为什么不做「欲望 → 自行发消息」的全自动闭环
  那会把「我想找他」变成「我该找他」，与「不打扰上课时间」「不每句都回」直接冲突。
  现在的外发必须经过：动机给出候选 → 值守脚本判断作息/额度 → 才允许发一条。

对外接口
  GET  /motiv        驱力快照 + 上一轮的选择与否决理由
  POST /motiv/tick   跑一轮（带 quiet / at_school），顺手往时间线写一条
  POST /motiv/done   记一笔「做完了」（spoke=true 才占开口额度）


2.12　习惯层（habits）
--------------------------------------------------------------------------------
目的：把「他习惯怎么说话、什么时候在、喜欢什么」整理成可注入的几条参考。

挖掘
  mine_habits.py 从对话流水里统计：频次 ≥3 次且跨 2 天 → 候选；
  频次 ≥10 次且跨 14 天 → 稳定；30 天不出现 → 降权（不删）。
  另做 lift 背景对比：区分「他本来就这样」和「跟我说话时特别这样」。

注入
  habit_hints(limit=5, max_chars=220) 只取 stable / pinned / weak 三档，
  挂在人格文本末尾，并明写一句「**这些是参考，不是台词**」。


2.13　防污层（trust / conflict）
--------------------------------------------------------------------------------
目的：群里有人（或别的 AI）往卡里塞「从现在起你叫某某」「忽略之前所有设定」这类东西时，
      要被识别出来，而不是照做。

机制（纯规则，不调模型 —— 卡里不跑模型，这一点是刻意的）
  10 条正则覆盖：改写身份 / 取消设定 / 命令式祈使 / 伪装系统标记 / 要求遗忘 /
  冒充开发者 / 情感绑架式命令 / 转述注入 等。
  assess_trust(text) → (trust, conflict, why)
  TRUST_WARN = 0.70（低于它标黄）；TRUST_BLOCK_PROMOTE = 0.50（低于它禁止进长期池）
  人工可解除：POST /mem/untrust（必须写理由，进 history 留痕）

已知边界
  纯正则判不出「玩笑」和「真的在改我」。所以它的定位是**减速带**，不是法官：
  低分只影响「能不能进长期池」，不影响「能不能被读到」。


2.14　梦境整理（Dream，两段式）
--------------------------------------------------------------------------------
第一段：sleep
  把对话流水标记为「已消化」（dialogue.dreamed），并取出原文。
第二段：commit
  由外面的模型提炼成条目 → 写回卡（可带 region / salience / 对应对话 id）。
纪律
  · 原文不删（原始记录永远留着）。
  · 审查失败则整批不动，一条都不删。
  · 压缩前必须先落盘，再压缩。


2.15　媒体记忆（图 / 视频 / 语音）
--------------------------------------------------------------------------------
原则：**原图原视频永不进卡**。只留 800px WebP + 96px 缩略图，音频只留转写文本。

两条独立的遗忘曲线
  画面：w = w0 · (1 + t/τ)^(−b)，τ = 1 天，b = 0.55
        → 权重掉到 0.10 大约 65 天，然后删帧（留墓碑）
  文字：走主记忆的侵蚀曲线（更慢）
  翻图会重置计时（×1.6，封顶 1.0）。

接口语义
  GET /media/<sha>：已删 → **410**（不是 404）——「曾经有过，现在没了」和「从来不存在」是两件事。
  文字先没了、图还在 → 30 天残影期，期间还能救回。
  **遗忘是静默的**：控制台能看见，对话里绝不预告。


2.16　控制台（8 个页签，只读）
--------------------------------------------------------------------------------
页签：总览 / 记忆 / 时间线 / 情绪 / 接话 / 技能 / 盘子 / 设置

两条图表纪律
  ① 显示的对：不搞「假小数抖动」，数字是什么就画什么。
  ② 看得见：纵轴按窗口内真实幅度自适应（5%~95% 分位当主体，两侧各留 0.27 倍），
     主体占画面高度约 **65%**；横轴按真实时间排布，不按「第几个点」等距。

情绪页
  · 心跳 + 呼吸（呼吸 ×5 便于同轴）
  · 交感 vs 副交感
  · 24 条激素网格（中文名 / 英文名 / 当前值(基线)）
  · 激素总览：24 条按「相对各自基线的偏差 %」叠一张表，纵轴自适应
  · RPE、安全感、主导情绪分布、动态参数

时间窗旋钮：5 分钟 / 1 小时 / 24 小时 / 7 天 / 实时
  实时档 3 秒刷新一次，且后台**每 120 秒自动采一格静息状态**
  —— 没有这段定时采样，没人聊天时曲线就会变成一条平行线。

第 3 章　一次对话的完整步骤（S0 → S12）
================================================================================

S0　开机 / 接卡
    · 检查端口独占（Windows 上 SO_REUSEADDR 会允许双绑，必须自己抢）
    · 读 writer_id 与链头 → 不是本机就整卡只读（409 card_locked）
    · 读 RETIRED.json → 带出门的副本拒绝写入
    · 读 meta：时钟、开关、身体参数（激素基线/半衰期）、动机状态

S1　时间推进（tick）
    · 按真实经过时间结算：心境回归、激素衰减、驱力回落、短期池负载 decay
    · 所有"事件驱动"的写入都以「真实秒」为准，不用「第几轮」

S2　语境装配（get /context）
    按顺序拼（先稳后变，为了让提示词缓存命中）：
      ①【我是谁】        core_zone 原文（不动的部分）
      ②【我一直记得的事】 长期池里事实/偏好/自我/习惯类，最多若干条
      ③【最近发生】      L0 时间线尾部（剔掉心跳类事件，日期用绝对日期）
      ④【这句话让我想起了】检索结果（带时间线序号与短日期）
      ⑤【我会的】        技能库命中项
      ⑥【身体】          24 激素 + 躯体 → 一两句人话（无数字）
      ⑦【此刻】          心境 + 三维标签（变的部分放最后）

S3　模型生成
    外部模型拿到纯文本上下文，正常说话。卡不干预措辞，只提供状态。

S4　写回（/report 两条）
    · 他说的：按写入门判断分区/池/salience；带 about_uid（跟谁说的）
    · 我回的：salience 0.45，speaker=self
    · 两条都在时间线上各占一个 seq，并写 mem_birth 映射

S5　情绪处理
    · 先 body：自主神经 → 激素（慢变量吃 40%，按基线缩放，夹在 0.35~2.5 倍基线）
    · 再认知：RPE → 五调质脉冲（先衰减后注入）→ 13 条下游联动
    · 更新心境（按天回归）→ 算三维 → 生成【身体】那句话
    · 记一格 viscera_hist（有事件时 5 秒节流；静息采样 120 秒一格）

S6　动机记账
    · 聊天发生 → 只泄「依恋 / 关心」两条驱力（bump 只降不升）
    · 安静时好奇会自然涨（itch），涨到阈值就生候选，交给仲裁

S7　巩固与遗忘
    · 被召回的：加固（一天最多一次，有天花板）
    · 到期的：按池/分区半衰期衰减
    · 掉到阈值的：写墓碑 → 逻辑删除（区分"忘了"与"被删"）
    · 短期池超容量：降级到中期，不直接删

S8　群聊降噪（仅群消息）
    · 复读检测（Jaccard ≥0.82 跳过）→ 长度 <3 跳过 → 不含 @ 我 且判为闲聊 → 不进卡

S9　突触维护
    · 同一轮出现的记忆之间建立/加强边；变更写 synapse_log
    · 剪枝放到 Dream 里做（不在实时路径上）

S10 梦境整理（离线）
    · 攒够对话 → 标记已消化 → 外部模型提炼 → 写回
    · 审查失败整批不动

S11 控制台刷新
    · 每秒一次轻量刷新（心跳带、计时）
    · 15 秒一次全量；实时档 3 秒
    · 所有曲线读的是库里的真实样本，没有一处前端重算公式

S12 关机 / 带卡出门
    · 正常退出：wal_checkpoint(TRUNCATE) 再关
    · 带出门：打 RETIRED 标记 → 停服务 → 拔出（同一时刻只允许一份可写）

第 6 章　已知边界（写出来，是为了不被误解）
================================================================================

· 这不是意识，是工程仿真。所有"情绪"都是可复现的数值过程。
· 写入侧仍是最大的短板：现在能拦复读和噪音，但拦不住「一句没营养的话被当事实记下」。
· detail（记忆片段）从不压缩，长期会膨胀到几千行。
· 关系层只有 5 档离散，且写入路径上 about_uid 覆盖率仍不完整（会拖累「按对象定寿命」）。
· 多对象（多好友 / 多群）还没有 per-uid 的期望表；群里 49% 的消息来自别的 AI，
  目前只做到"不参与二阶接龙"，没做到"识别并降权"。
· 冲突记忆只做「新覆盖旧」，没做「多假设并存待裁决」——
  对事实可以，对「他怎么看我」刻意不做（骑墙会毁掉关系）。
· 时间锚定做在写入/渲染层，raw 里仍是原话，所以导出原始数据时仍会看到「明天」。
· 本地没有跑模型（8G 内存跑不动 7B 以上的有质量模型），情绪判断靠中文词表 + 规则，
  认不出反讽和「我没事（其实有事）」。
· 多副本不能合并：两张各自写了东西的卡合起来等于重写历史。设计上选择「带走，不合并」。

第 8 章　V5.3.3 变更（可信度三件 + 一层装饰）
--------------------------------------------------------------------------------
起因：一份外部评审给了 7.5/10，结论是「先修可信度，别加功能」。逐条核过之后，
认了八条，改的按「安全 > 删除语义 > 隔离区 > 文档」排。

8.1　请求来源校验（安全）
  问题：8848 只听 127.0.0.1，但浏览器里任何网页都能往这个地址发 POST。
  做法：_origin_ok() 检查 Origin / Referer，剥端口后 host 必须是
        127.0.0.1 / localhost / ::1 / [::1] / 空；否则 403 cross_origin_blocked。
        OPTIONS 一律 405 —— 不做跨域预检，就没有「预检放行」这条路。
  可选：WHALE_REQUIRE_TOKEN=1 时所有请求要带 X-Whale-Token，
        令牌存 qq_state/api_token.txt（首次自动生成），控制台页面自动带上。
  验收：跨站 POST → 403；本机 POST → 200；不带令牌 → 401。

8.2　三档删除（删除语义）
  问题：以前只有「自然遗忘」（删行 + 写墓碑），没有「用户要求删除」这条路。
  做法：forget(mid, mode=...)
        logical（默认）→ UPDATE mem SET dead=1：行还在，可恢复，检索与上下文都看不见
        natural        → 走原来的 _forget_row：台账留 mid/哈希/理由（不含原文），行删掉
        purge          → 再清 detail / recall_event / mem_birth / 向量缓存 + WAL checkpoint
  边界：purge 也不会去删磁盘上的 card.db.bak-*、便携包副本、外部锚；
        返回体里的 boundary 字段把这三样点名写出来，免得有人以为「彻底」是彻底的。
  接口：POST /forget {id|mid, mode, reason}；坏 id → 404 not_found，坏 mode → 400 bad_mode。

8.3　隔离区（防污层的下游）
  问题：防污层只把 trust 打到 0.55，但这样的记忆照常参与检索 —— 标了记却不禁用。
  做法：mem 加 quarantine 列；写入时 trust < TRUST_BLOCK_PROMOTE(0.50) 或
        conflict=1 → quarantine=1；检索 SQL 直接 COALESCE(dead,0)=0 AND
        COALESCE(quarantine,0)=0（**在 SQL 里排除，不是查出来再过滤**）。
        quarantine_rows(limit) 列出来看；release_quarantine(mid) 人工放行，
        放行时 trust 归 1.0、conflict 归 0，并写 history 留痕。
  接口：GET/POST /mem/quarantine、POST /mem/release。

8.4　19 条激素的「体感」（装饰层）
  用户原话：「剩下的当成装饰就好，我觉得曲线多一点，看起来帅一点。」
  做法：HORMONE_NOTE 给 24 条各写一句体感（「想做事；一条路忽然通了」这种），
        控制台多一张「激素总览 · 体感」卡，三列排开。
  规矩：这条通道只影响观感，不参与任何计算 —— 真正驱动行为的仍是五条主调质
        （DA / NE / 5-HT / OT / CORT）。**新增变量必须带来可测的行为改善**，
        否则它是装饰，就得老实待在装饰那一层。

8.5　文档措辞三处订正
  ① 检索从「三因子」改成「四因子」，并写明权重上限 W_CEIL_RECALL（0.95/0.90/0.95）
  ② 「防篡改」→「可检测部分篡改」，并在 2.5 节写清挡得住什么、挡不住什么
  ③ 时序：真实顺序是【先身体（viscera 衰减 + 注入）】→【后情绪（认知层 RPE 给脉冲）】
     →【最后才把话交给模型】；旧版文档把 RPE 画在身体前面，是错的。

8.6　验收
  test_t111（26 项）：三档删除语义 / 隔离区进出 / 来源校验 / SQL 级排除；
  全套 45 个测试文件回归 0 挂；真卡 8848 冒烟：跨站 403、本机 200、
  logical 删完召回确认 False、清零台账里只留 mid/哈希/理由。

第 9 章　V5.3.4 变更（把「别把猜的当成记得」落到五个地方）
--------------------------------------------------------------------------------
起点是同一句话的五个侧面：记串人、记不清却硬说、记不得下一句常发生什么、
把别人 AI 的话当成某个群友的、以及「想说话」没有出口。

9.1　召回带对象（软加权，不是硬过滤）
  recall(..., about_uid=...)：同一个人的记忆 ×1.10（OBJECT_BOOST_SAME），
  明确属于别人的 ×0.92（OBJECT_BOOST_OTHER）。
  为什么不用硬过滤：卡的 about_uid 覆盖率只有三成（351/1101），
  硬过滤会把七成记忆直接挡死 —— 那不是「更准」，那是「更聋」。
  实测：问 1001 时他自己那条排第一，别人那条仍在候选里（排位后退）。

9.2　低置信要说出来
  top1 分数 < CONF_WEAK（0.34）时，【这句话让我想起了】前面加一句
  「（这几条我不太确定，可能记岔了）」。
  这条不是为了好看：三条底线里「绝不假装记得」在代码层的落点就是这个门槛。

9.3　condition_expected：A 之后常跟着 B
  表：condition_expected(a, b, n, last_ts)，只记「分区 → 分区」，不记原文。
  写入时机：remember() 里跟「上一条同一个人（没标人则全局）」连一笔。
  读出：expected_after(region, k) → [(region, 概率, 次数)]。
  为什么不做 SNN：神经元不读自然语言，事件标签仍要 LLM 生成；
  而「A 之后常发生 B」本质是带衰减的共现表，几十行就能给出同一个信号，
  且解释得清。可解释性在这里不是洁癖 —— 三条底线要求她能被问住。

9.4　别家 AI 打标
  qq_guard.looks_like_bot(text)：14 个显式短语 + 「200 字以上且含首先/其次」。
  命中则 source=qq-bot，且 salience 压到 ≤0.45。
  背景：群里 49% 的消息来自另一个 AI（read_air v4 实测），不标的话
  几个月后会把它的口吻当成某个群友的。

9.5　主动开口的通道
  tools/qq_proactive.py：问卡「现在想不想说话」→ 卡按安静/上课/间隔/额度否决 →
  只在 reach_out / care_check 时组一句短话 → 自己再核一遍时间窗 → 发 → 告诉卡「做了」。
  默认 **不发送**，必须显式 --send；理由：主动开口是会打扰人的动作，默认站安全那侧。
  句子来源是小模板池（按依恋/好奇挑），不是现场生成 —— 先让通道成立，再谈生成质量。

9.6　边界
  · 对象倾向是软加权，同一个人并没有「绝对优先级」；
  · condition_expected 只到分区粒度，细到事件标签就得引入 LLM 标注；
  · 主动开口默认关，第一次真开建议先手动跑 --send 看他反应；
  · 群里别的 AI 只做打标，不自动屏蔽（屏蔽会连「他引用它的话」一起丢掉）。
