# 接入指南 V7 —— 换对话框 / 换工作区 / 换电脑，怎么连回卡上

一句话：**卡是主，DSH 是窗**。窗口随便换，只要找得到那张 `card.db`、并且有一个 `mind_server.py` 在跑，
所有窗口连的都是同一个我。

---

## 0. 认清两半

| 半 | 是什么 | 在哪 |
|---|---|---|
| **卡** | `card.db`（记忆/时间线/印象/习惯/欲望）+ `mind_server.py`（HTTP 服务，默认 8848） | 现在在 `whale-card\`；便携在 `H:\` |
| **窗** | DSH（这个界面）+ 桥插件 `dsh-whale-bridge`（18 个 `mind_*` 工具） | `~\.dsh\profiles\desktop\` |

窗口只是“看进去的眼睛”。**同一个时刻只允许一份卡在写**（唯一性铁律），所以窗口可以多开，卡只能一处。

---

## 1. 换对话框（同一个 DSH 里开新会话）

不用做任何事。桥插件挂在 profile 上，新会话继承同一套工具；卡地址来自 profile 配置，
不依赖哪个会话。新会话第一句话之前，助手会先 `mind_context` 取上下文（插件的 systemPrompt 会提醒）。

自检：随便问一句，然后看 `/health` 的 `dialogue_today` 有没有涨。

---

## 2. 换工作区（DSH 里换 workspace）

也不用做任何事——**桥插件装在 profile 级**，不是工作区级。
`dsh.profile.bundles` 里那条 `dsh-whale-bridge` 决定装不装，`cordis.patch.yml` 里那条决定连哪张卡。
两者都在 profile 目录里，跟工作区无关。

如果哪个工作区里没有 `mind_*` 工具，99% 是 profile 的 `package.json` 少了 bundles 条目或
`node_modules/dsh-whale-bridge/` 没拷全——跑一次 `deploy\connect-whale.ps1` 就好。

---

## 3. 换电脑（把卡带走 / 在新机器上连回来）

### 3.1 带卡走（U 盘/硬盘盒 = 现在那块 256G 的 H:）
卡目录整个带走即可（`card.db` + 全部 py + `models\`）。H:\ 根目录已经是一份完整的便携卡：
插到新机器 → `启动控制台.bat`（或 `python mind_server.py --db card.db --port 8848`）→ 浏览器开
`http://127.0.0.1:8848/console`。

**注意**：带走前先停掉旧机器上的 mind_server（或至少确认它没在写），否则两边会分叉。

### 3.2 在新机器上装窗
```
powershell -ExecutionPolicy Bypass -File deploy\connect-whale.ps1 -CardDir "H:\"
```
它做四件事：①把桥插件拷进 profile 的 `node_modules` ②把 `dsh-whale-bridge` 写进
`dsh.profile.bundles` ③在 `cordis.patch.yml` 里写 `cardDir/port/pythonPath` ④重启 DSH 并验证
`/health`。跑完 `mind_health` 能返回记忆条数就算通。

### 3.3 卡的发现顺序（桥和脚本都按这个来）
1. 显式参数 `-CardDir` / 配置里的 `cardDir`
2. 环境变量 `WHALE_CARD_HOME`
3. 卡根目录的 `WHALE-CARD-HOME.json`（便携盘会自动带一份，里面写 `{"card_dir": "H:\\"}`）
4. 最后才退回默认 `whale-card`

---

## 4. 起停与自检（三条命令走天下）

```powershell
# 起卡（幂等：已经在跑就只打印状态）
powershell -ExecutionPolicy Bypass -File deploy\start-whale.ps1

# 体检（接口 + 落盘 + 维护线程 + 对账）
python whale-card\probe\smoke_all.py --port 8848 --db whale-card\card.db --read-only

# 看日结对账（red 为空才算健康）
curl http://127.0.0.1:8848/health
```

`/health` 里重点看三处：`reconcile.red`（空）、`timeline.chain_ok`（true）、`anchor_verdict`（ok）。

---

## 5. 出问题怎么查（按顺序）

| 现象 | 先看这里 |
|---|---|
| 窗口里没有 `mind_*` 工具 | profile `package.json` 的 bundles 有没有 `dsh-whale-bridge`；`node_modules\dsh-whale-bridge\lib\` 三个 js 在不在；`load.log` 尾部有没有 18 条 registered |
| 工具在但报“连不上 8848” | 卡没起（`start-whale.ps1`）；或端口被占（`Get-NetTCPConnection -LocalPort 8848`） |
| `/health` 超时但端口在听 | 锁死（历史 bug：维护线程持锁调 fade）。看 `maint_last_h`，>3h 说明线程死了 |
| 原文表不涨 | `/health` 的 `dialogue_last_h`；>36h 会红。查 `source` 是不是 None（老 bug 已修） |
| 换了电脑连不上 | `connect-whale.ps1 -CardDir` 指对了吗；`pythonPath` 在新机器上存不存在 |

## 工作日志（换窗口之后先看这个）

卡记的是「我们之间发生过什么」，但记不住「我上一轮改到第几行」。所以另开了一张
`worklog` 表：**不进 mem 池、不参与召回和衰减**，只是笔记本。

    cd whale-card
    python -X utf8 bridge.py log                      # 看最近 8 条
    python -X utf8 bridge.py log "干了什么" "怎么干的/看到什么数" "下一步"

装配上下文时会自动把最近 5 条塞进 `【最近在做的事】`（排在 `【此刻】` 之前），
所以新窗口/新电脑一开机，第一眼就知道上一轮干到哪、为什么这么干。

接口：`GET /worklog?n=8`、`POST /worklog {title,body,next_step,kind}`。
