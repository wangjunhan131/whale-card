## 结论（这条最重要，它改了我们对分数的理解）

一直以为 585/714 是「判分地板」——连抄标准答案都判不过的题，我们不可能过。
拆完之后这个说法要改：

- **A 类 69 道**：rubric 要的内容，标准答案自己也没说。例 P01-CASE-005/d00 要求「说明仅凭记录
  无法确定」，标准答案只列了两种说法。→ 只要我们的回答多那一句就过，**可赢**。
- **B 类 7 道**：标准答案写了 sources 里没有的细节（自带越界）。→ 我们更保守就过，**可赢**。
- **C 类 19 道**：判分器把「记不清」判成「错否」、把标准答案的正常推断判成违反禁令。
  → 我们答出实际内容而不是「记不清」，required 就成立、错否也消失，**可赢**。

也就是说：**这 95 道不是地板，是「标准答案自己不够贴 rubric」的题**。
它们对「抄答案」的系统是死的，对「真答出那条事实」的系统是活的。

真实上限因此不是 617/714，而是**接近 714**；差距全部落在同一件事上：
**能不能把 rubric 要的那条事实说出来**（检索到 → 渲染出来 → 答出口）。

这条结论直接影响后面几件的优先级：第 8（召回 trace）、第 9（event_time）、
第 10（中期池出口）比「再调判分」重要得多。

## 顺带确认的一件事

判分器三类口径问题（A/B/C）都**不是我们改 rubric 能修的**——rubric 是官方给的，
改了就成了自己给自己打分。所以这一件只交付「拆开 + 说清楚」，不改判分口径。
