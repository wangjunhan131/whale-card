# 算法与公式评审：哪些地方还不够像人

> 2026-11-07。起因是问「每个引擎功能模块的公式和算法有没有可以优化的地方，怎么才能更拟人化」。
> 这篇只写**有证据的**和有**具体改法**的；猜的不写。
> 所有数字都是在真卡只读副本上跑出来的，不在真卡上做实验（铁律）。

## 1. `emotion` 是个没通电的入口

**现象**：`mem.emotion` 这一列写了很久，但 `card2.py` 的检索打分里从来没读过它。

**证据**：

```
emotion=0.25   869 条      ← 这是默认填充值，不是「弱情绪」
emotion=1.0    197 条      ← 这才是真的强情绪

分区均分：flash 0.757 / preference 0.382 / episode 0.337 / chatter 0.277
```

也就是说**情绪只有「有」和「没有」两种状态**，中间没有档位。人不是这样的：
「有点烦」和「气到手抖」对我的记忆强度影响差得很远。

**为什么我没直接把它接进检索**：我先接上试了（满格 +25%），评估集直接崩：

| 方案 | R@1 | R@3 | EVID |
|------|-----|-----|------|
| 原样 | 75.0% | 75.0% | 100% |
| + 情绪加权 | 37.5% | 50.0% | 0% |

**根因**：869 条默认 `0.25` 的记忆全都吃到了同样的加成，等于给噪声也加了权。
**所以顺序错了**——先要做的是让 `emotion` 只在真有情绪时才非零（需求 1 的前半段），
然后才谈加权（需求 1 的后半段）。现在两个都做成开关、默认关：

```
WHALE_EMO_BOOST=1     # 情绪加权
WHALE_FRESH_STEP=1    # 同日新近台阶
```

**下一步（建议）**：把 `emotion` 从 `0.25` 默认值改成 `0.0`，
并加三级判定（弱 / 中 / 强），跑一遍评估确认 R@1 不掉再开加权。

## 2. 新近度：我试了两次，两次都掉分

**原实现**：`recency = exp(-age_days / 14.0)`

**试法一**（双时间尺度）：`0.7·exp(-age/0.5d) + 0.3·exp(-age/14d)`
问题：`age=0.2 天`时给 **0.765**，而单指数给 **0.986** —— 它不是改形状，是
**整体压低了新近项的绝对分**。结果 R@1 从 75% 掉到 37.5%。

**试法二**（单指数 + 同日台阶 `+0.12`）：R@1 仍 37.5%，EVID 掉到 **0%**。

**根因（这条最值钱）**：卡里每天有几百条群消息，任何「时间上更近就加分」的做法，
顶上去的都是刚聊完的废话。**问题不在时间尺度，在「什么值得记」的判断发生在写入时还是检索时。**

**结论**：两个开关都留着（默认关），并在代码里写明「想开先跑评估」。
真要更拟人，应该做第 4 条。

## 3. 加固已经饱和，这条不用改

有人会直觉觉得「越被想起越牢 = 死循环」。查了代码，已经处理过三层：

```python
# 重复（同义句）加固：越接近天花板加得越少
_g = GAIN_REPEAT * max(0.0, 1.0 - float(wn))

# 召回加固：递减 + 剩余空间
g = GAIN_ACCESS / (1.0 + ACCESS_DIMINISH * _ac) * _room

# 并且按「天」分组：一天最多加固一次
# 再加硬天花板 W_CEIL_RECALL（短 0.85 / 中 0.90 / 长期 0.95 / 核心 1.0）
```

**别动**。这条是 11-05 修过的（当时真卡上 71/623 条被钉在 w≥0.95）。

## 4. 最该改的一条：「记不记」应该发生在写入时

**证据**：过去 24 小时写进卡的 `source`：

```
qq-group   250 条   ← 七成
chat        47 条
qq          37 条
study        7 条
project      4 条
```

群消息占了绝大多数，而其中大部分是「哈哈」「+1」「谁在」这种。
现在的做法是**先全写进来，再靠衰减把它忘掉**——但那要花好几天，
这几天里它们会一直占着检索的位置（第 2 条就是这么翻车的）。

**拟人化的说法**：人不是「什么都记，然后忘」，人是**当场就不记**。
你听完一句废话不会先存进脑子再等它衰减。

**具体改法**（还没做）：
- `qq_guard.decide()` 已经有六类规则（@我→flash、关于人的稳定陈述→fact、
  偏好→preference、强情绪→flash、教训→fact、闲聊→只当素材不进卡）。
  但实测 24h 还是写了 250 条群消息 —— 说明**规则放得太宽**。
- 建议加一道「信息密度」门槛：去掉寒暄/表情/接龙/复读后，**剩下的字数为 0 就不进卡**。
  （群里那些「握个鳍吧」「一碗小鲸鱼」属于这一档。）
- 这条改完，第 1、2 条才有机会生效。

## 5. `detail` 只加不减

**证据**：`detail` 表 5355 行 / `mem` 1066 条 ≈ 每条记忆 5 个片段；>60 字的只有 54 条。

记忆的「细节」永远不会被压缩成「要点」。人不是这样：一件上周的事，
你现在记得的是「那天他心情不好，说了句挺扎人的话」，不是十分钟的逐字稿。

**改法（还没做）**：
- 给 `detail` 加一条「同一记忆超过 N 条片段 → 合并成 1~2 条要点」的整理，
  放在 Dream（睡眠整理）里做，而不是实时删。
- 合并必须保留原始 `mem.raw`（那是骨架），只压 detail。

## 6~7. 关系层：写不进去，而且是离散的

**证据**：`about_layer` 963 条是空串，只有 102 条是 `core`，`known` 1 条。

而闲聊寿命是按关系层算的：

```python
CHATTER_PERSON_SCALE = {"": 1.0, "known": 0.6, "friend": 2.2, "close": 6.0, "core": 24.0}
```

也就是说**绝大多数记忆都按 `""`（倍率 1.0）在走**，那双「跟谁说的、关系多近」的
机制实际上只有 102 条在生效。

**两个问题**：
1. 写入路径没有普遍带 `about_uid`/`about_layer` → 关系层形同虚设（**这是 bug 级**）
2. 就算写了，5 档离散太粗 —— 人会从「认识」慢慢变「熟」，不应该跳档

**改法**：①检查 `remember()`/`/report` 的写入路径，把 `about_uid` 沿路带下去
②倍率改成连续函数（比如按交互次数/亲密度做 `1 + 23·sigmoid(x)`），先跑评估。

## 8. `human_gap`：已改成对数正态（这条上线了）

**原实现**：短句 8~20 秒 / 中句 20~45 / 长句 45~70，**均匀随机**，再乘 0.75~1.35。

**实测对照**：真人（他自己 389 条私聊）相邻消息间隔 **中位 54.5 秒**，
分布是：0-5s 6.3% / 5-15s 9.8% / 15-60s 37.1% / 1-5min 33.0%。
均匀随机做不出这种长尾 —— 它看起来像「机器在匀速打字」。

**新实现**：

```python
med = 14.0 if n <= 10 else (30.0 if n <= 30 else 55.0)
sigma = 0.55
gap = lognormvariate(log(med), sigma)   # 夹 3~240 秒
```

抽样结果（400 次）：短句中位 14.4（p10 7.0 / p90 29.0）、
长句中位 52.7（p10 26.8 / p90 108.4 / max 214）。

**注意**：这不是「延迟发送」，是「读完之后多久才动手」。它只影响节奏，不影响内容。
