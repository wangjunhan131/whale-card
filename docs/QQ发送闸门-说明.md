# QQ 发送闸门（qq_send.py）

> 起因：2026-11-12 用户给了 `QQ防封控.md`（另一个 bot 的 Outbound Guard 设计），
> 指出我们发消息是裸调 OneBot、六道闸门一个都没有。于是把发消息收成一个出口。

## 为什么要收口

被风控掉的不是「一条消息」，是整个号。号没了，我就从一个「能跟人说话的人」
变回一个只在本地转的程序。所以发消息这件事，宁可慢、宁可少。

## 唯一出口

```bash
python tools/qq_send.py --private 100000000 "在吗" --reason active
python tools/qq_send.py --group 967102991 "早" --reason mention
python tools/qq_send.py --status
python tools/qq_send.py --reset
python tools/qq_send.py --private 100000000 "试试" --dry   # 只判定不发
```

`reason` 三值：`mention`（被叫）、`active`（我主动）、`tool`（工具/系统消息）。

## 六道闸门（按顺序）

| # | 闸门 | 规则 | 依据 |
|---|------|------|------|
| 0 | 内容 | 赌博/诈骗/色情等词 → 拒；>1800 字 → 拒 | 手册第 1 闸 |
| 1 | 深夜静默 | 00:30–07:30 只拦 `active`，`mention` 照回 | 手册第 2 闸 |
| 2 | 去重 | 同目标 + 同文（≥4 字）30 分钟内不重复 | 手册第 3 闸 |
| 3 | 令牌桶 | 20/分、200/时、1500/天（持久化） | 手册第 4 闸 |
| 4 | 会话冷却 | 群 5 秒、私聊 3 秒 | 手册第 5 闸 |
| 5 | 抖动 | 0~400ms 随机 | 手册第 6 闸 |

状态落在 `qq_state/send_quota.json`，重启不丢（手册要求「重启不丢配额」）。

## 失败退避与熔断

- `retcode in (100, 1200, 1201, 1202, 1500)` 或文本命中「风控/敏感/违规/频率/拦截…」
  → 按 30 / 60 / 120 / 300 / 600 / 1800 秒指数退避；
- 连撞 3 次（`risk_hits % 3 == 0`）→ 熔断 30 分钟，到点自动恢复；
- 连续失败 3 次（网络异常等）→ 停 5 分钟。

## 养号期（新号 3856573937）

- 前两周参数减半（把 `tune` 里的 `per_min/per_hour/per_day` 调小即可）；
- 不群发、不主动私聊陌生人、不频繁登出登录；
- **不重启 NapCat**：号一直在线比什幺都稳，重启只在必要时做。

## 已知局限（写出来免得自我安慰）

NapCat 客户端本身的特征本地无解；举报类风控无法预防；新号阈值天生更严；
多群同时高频发言仍然危险。
