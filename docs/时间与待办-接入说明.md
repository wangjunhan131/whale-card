# 时间与待办（tempora）接入说明

2026-11-11 接入。起因：早上用户说「我到学校了」，我在同一轮里把它当成「今晚」——
不是记错，是手上没有一行「现在几点」。

## 做了什么

1. `tempora.py`（新模块，约 300 行）
   - `now_line(ts)`：`现在是 2026-11-11（周三）中午 12:59`，**每轮装配上下文的第一行**。
   - `resolve(text, ts)`：时间词 → 绝对时间窗（day / part / soon / no_time / need_ask / none）。
     长词先匹配（「明天早上」不会被「明天」抢走）；凌晨 0–4 点说「今晚」按昨夜算并打
     `ambiguous_night`；「改天/回头/有空」→ `no_time`（不说时间就是不催）；「月底/年底」→
     `need_ask`（宁可不记也不猜）。
   - `EventStore(conn)`：`tevent`（约定/状态，带 expect_time/expect_end/status/importance/
     subject/source/raw_text/meta）+ `tstate`（我在哪、在做什么这类可变状态）。
     - `add_plan()`：有将来时间窗才落库；`sweep()`：过了点 → `expired` 并给出 `late_hours`；
     - `block_text()`：拼【现在】+「我这会儿在：…」+【没到点的事】+【过了点没做的】。
2. 接线
   - `card2.assemble_context`：在【此刻】之前插这一段，`sections["time"]` 记字数。
   - `cardmix_store.remember`：写完记忆顺手记约定（用**未锚定**原句，因为 `normalize_time`
     会把「明天早上七点」改写成「11月12日早上七点」，再认时间词就只剩「早上」）。
     他说的和我说的都记，`subject` 区分是谁许的。
   - `mind_server._start_maintenance`：每跳 `sweep()`，过期立刻可见。
   - 开关：`WHALE_TEMPORA=0` 关；`WHALE_MAINT_SEC=0` 时没有自动结算（手动跑服务会看到）。
3. 自测 `probe/_tempora_test.py`（副本 + 临时端口，不碰活卡）：**14/14 PASS**
   - 纯函数 7 条：now_line 有日期与时段、明早→明天 6–9 点、凌晨「今晚」→昨夜+ambiguous_night、
     白天「今晚」→今天 18–23、改天→no_time、月底→need_ask、无时间词→none。
   - 账本 4 条：约定落库、no_time 不落库、pending 可见、过期带 late_hours（46.5h）。
   - 端到端 3 条：`/remember` 200 → `/context` 的 `sections` 有 `time`、prompt 有「现在是」、
     prompt 有「没到点的事」。
   - 活卡实测：`/health` 全绿、`/context` 十二格 + `time:26`、prompt 首行「现在是 …」。

## 踩到并修掉的三个坑

1. 时间词表按声明顺序匹配 → 「明天早上七点」先命中「明天」，时间窗退化成整天。改成**按词长倒序**。
2. 在 `remember()` 里 `executescript` 建表 → 那时可能正开着事务，报
   `cannot start a transaction within a transaction`，被 `soft_fail` 吞掉后表现成「一条都没记上」。
   改成建表放 `_init_schema`（`tempora.ensure`），`EventStore.__init__` 只在缺表时兜底。
3. 只给 `speaker=="user"` 记约定 → `/remember` 默认 `speaker="self"`，测试里一条都没落。
   改成两边都记，`subject` 区分。

## 钟点：准点基线 + 容差窗（2026-11-11 加）

用户原话：「3点钟和3点钟左右是两个概念……给一个范围是对的，但是那个范围不能太大。正负半个小时或一个小时就差不多了。
当然同时也要加入一个所说的准点作为基线」。

| 说法 | 准点基线 | 容差 | 落库窗口 |
|---|---|---|---|
| 三点 / 下午三点 / 15:00 / 十五点 | 15:00 | ±30 分 | 14:30–15:30 |
| 三点左右 / 大概三点 / 三点前后 | 15:00 | ±60 分 | 14:00–16:00 |
| 三点半 / 三点一刻 / 三点零五 / 三点二十五 | 15:30 / 15:15 / 15:05 / 15:25 | ±30 分 | ±30 分 |
| 今晚三点 | 次日 03:00 | ±30 分 | 次日 02:30–03:30 |
| 下午三点到四点 | 15:00–16:00 | 0（区间两端都准） | 15:00–16:00 |
| 三点多 | 15:00 起一小时 | 0（单边） | 15:00–16:00 |

实现：`_clock_window()` 返回 `base`（准点）与 `tol_min`（容差分钟），`resolve()` 把 `start=base-tol`、`end=base+tol`；
`EventStore.add_plan` 把整份窗口写进 `meta`，`reason` 记成 `time_word=15:00 ±60 分  tol=60min`。
`flags` 会标 `hour_guessed`（没说上下午、按「现在」猜的）与 `ambiguous_night`（凌晨 0–4 点说的「今晚」）。

修过的四个坑（都有复测）：①`十五点` 这类复合中文数认不出 ②`今晚三点` 被算成下午 15:00（该是次日凌晨）③`三点零五/三点一刻` 分钟被吞
④`明天下午三点左右` 被「下午当成晚上」多推一天、`三点到四点` 末端跨到隔天。

复测：`probe/_tempora_test.py` 14 项 + 钟点九条（八条对，`三点零五`/`三点一刻` 修完后九条全对）；
副本端到端：`/remember`「明天下午三点左右我要去学校开家长会」→ `tevent` 14:00–16:00（宽 120 分）、
`/context` 里出现【没到点的事】那一行、`sections.time=76`。


## 约定时间 与 实际时间（两笔账）

「规定 7:20 到校」和「我实际 7:15 走进校门」是两件事，中间天然有误差。系统现在分开记：

- **约定**：`tevent.expect_time`（准点基线）/`expect_end`（窗口）、`meta.base`（准点）、`meta.tol_min`（容差）。三点=15:00±30、三点左右=±60、三点到四点=两端都准、三点多=单边一小时。
- **实际**：`tevent.actual_ts`。两种来源——
  1. 一句话里两个钟点：「学校要求7:20到校，我7:15就到了」→ 第一个当约定、第二个当实际，直接算「早 5 分」。
  2. 事后补一句：「我终于到学校了，7点28到的」→ `note_actual()` 按话题词找那条 pending 约定，把说出的钟点**贴到约定那天**（±1 天、上下午两个候选取离约定最近的），再相对**准点**算 `早/晚 N 分`，写进 `reason`。
- 迟到/早到永远相对 `meta.base`（准点）算，不相对窗口起点，否则「早到 5 分」会被算成「早 35 分」。
- 话题匹配剔掉时间类二字片（`_topic_tokens`）：否则「7点」两边都有，会把「开会」的补报扣到「到校」那条约定上。
- 已验：A 7:20 约 + 7:15 到 → 早 5 分；B 7:20 约 + 7:28 到 → 晚 8 分；C 8:00 开会 + 7:45 到 → 早 15 分（不再误配到 7:20）；E 15:00 看画展 + 16:10 到 → 晚 70 分。
- 坑：`pending()`/`recent_expired()` 原本 `dict(r)`，连接没有 `row_factory` 时抛 `TypeError: cannot convert dictionary update sequence element #0 to a sequence`，已改成按 `cursor.description` 自己装字典。
