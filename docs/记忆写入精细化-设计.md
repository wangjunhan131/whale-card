# 记忆写入精细化：字段、规则与召回用法

> 目标：写入端把一条记忆拆细、打标准标签；召回端用得着这些标签，而不是只有一根向量。
> 现状基线：2.2 开发集证据轮命中率 **36.5%**（417 题严格口径，2026-11-13，融合版）。

## 一、为什么要拆

现在一条记忆 = 一个向量 + 一句原文。长句里「几点、在哪儿、跟谁、干什么」全糊在一起，
问「上次那只猫多重」时，向量只能模糊地靠近，分不清是哪一次。

人回忆不是这样：先想「哪阵子」→「在哪儿」→「跟谁」→ 才想起原话。
所以写入端要把这四样拆成可检索的字段，召回端按它们做软投票。

## 二、字段（mem 表新增，全部可空，老数据保持原样）

| 字段 | 含义 | 取值 |
|---|---|---|
| `who` | 涉及的人（逗号分隔的实体名） | 我 / 用户昵称 / 群友昵称 … |
| `whom` | 记忆的主体（这条在说谁） | 同上（默认＝谁说的） |
| `where` | 地点 | 家 / 学校 / 公司 / 猫舍 / 医院 …（复用 `split_memory` 已识别的地名） |
| `ev_kind` | 事件类型 | 吃饭 / 看病 / 上班 / 上学 / 买东西 / 玩 / 吵架 / 承诺 / 闲聊 / 其他 |
| `ev_ts` | 事件发生时间（已有 `event_ts`） | epoch 秒 |
| `prec` | 时间精度（已有 `event_precision`） | 分钟 / 小时 / 天 / 模糊 |

规则：
1. **一条记忆只描述一个「事件片段」**——按标点切句后，每句独立成条，不再塞多个事实。
2. 抽不出的字段留空，**绝不猜**；留空在召回时那一路权重直接归零。
3. 同一段话里的代词（他/她/它）按上下文回填到 `who`，回填不了的留空。

## 三、召回端怎么用（不做硬过滤，做软投票）

```
候选 = 三路并行召回各取 Top-N，合并去重
若问句带时间线索：候选内按 |事件时间 − 问句时间| 衰减加权
若问句带地点/人物：候选内有交集者加权，无信息时不加不减
最终 Score = 文本相关度 + α·时间吻合 + β·地点吻合 + γ·人物吻合
```

- **没有某一项 ≠ 扣分**：`where` 为空的记忆不因「答不出地点」被淘汰。
- 交叉优先：同时命中时间与人物 > 只命中一项 > 都不命中（这正是「交叉对比」）。

## 四、真实对话 vs 评测，两条策略

| 场景 | 策略 |
|---|---|
| 日常聊天 | 线索太少（「上次那只猫」）→ **直接问一句「哪一次？」**，像人一样；不硬猜 |
| 评测 / 不能追问 | 只能取最可能的那条；返回时带 `confidence`，低置信度就在正文里说「记不清是哪次」 |

这一条很重要：追问是人的正常行为，不是系统缺陷；但评测里没有追问机会，所以两条路要分开。

## 五、实施顺序（每一步都用同一把尺子量）

1. 写入端加字段 + 按句拆条（不动召回，先看「记忆条数/检索耗时」是否可接受）。
2. 召回端加软投票（时间/地点/人物三路），对比 36.5%。
3. 模糊问句 → 追问策略（只影响真实聊天，评测里关掉）。
4. 数字达标后再考虑上生产（默认开关关，先副本跑）。
