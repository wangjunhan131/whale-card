# 数字生命卡 · 使用说明（V7）

这份说明写给「拿到卡、想把它跑起来」的人：不要求你会写代码，但要能照着敲几行 PowerShell。
它只讲三件事——**第一次部署**、**换一张卡**、**把卡带到另一台电脑**，每一步都写清「怎么确认成功」。
命令都按 Windows PowerShell 写，路径以本机的 `whale-card` 为例，换成你的实际路径即可。
没验证过的地方我会明说「待确认」，不猜。

---

## 0. 先认清三样东西，和一条铁律

| 东西 | 是什么 | 在哪 |
|---|---|---|
| **卡** | 一个目录。`card.db` 是记忆本体（SQLite，WAL 模式），`*.py` 是引擎，`models\` 是向量模型 | `whale-card` |
| **服务** | `mind_server.py`，只听 `127.0.0.1:8848`，**没有账号密码**，只给本机用 | 卡目录里 |
| **窗** | DSH 里的 `dsh-whale-bridge` 插件，注册 18 个 `mind_*` 工具，每轮先问服务 | `%USERPROFILE%\.dsh\profiles\<profile>\node_modules\dsh-whale-bridge` |

**铁律：同一时刻只有一份卡能写。** 换卡、搬家、从 U 盘接回来，全都是在守这一条——守不住就会出现「两份拷贝各写各的，然后互相覆盖」。

四个双击入口（都是薄壳，真正干活的是 `tools\` 里的 Python）：

| 双击 | 实际执行 | 干什么 |
|---|---|---|
| `一键落地.bat` | `tools\first_run.py` | 体检 → 落地 → 交棒 → 起服务 → 试写 → 开控制台 |
| `启动控制台.bat` | `tools\open_console.py` | 确认服务活着，开 `http://127.0.0.1:8848/console` |
| `接入DSH.bat` | `tools\install_to_dsh.py` | 把桥插件装进 DSH profile 并写好连接配置 |
| `接回来.bat` | `tools\come_back.py` | 把 U 盘上的卡接回本机，U 盘转只读 |

## 1. 部署：从零到跑起来

### 1.1 系统层：先对时间

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11 64 位 |
| 运行库 | VC++ 2015-2022 x64 |
| 时间服务 | `w32time` 必须是 **Running**、**自动**启动 |

```powershell
sc config w32time start= auto
net start w32time
w32tm /resync
w32tm /query /status
```

**怎么确认**：`Get-Service w32time` 的 Status 是 `Running`；`w32tm /query /status` 里有「源:」和刚才的「上次成功同步时间」。

**为什么较真**：卡有「时间感」，遗忘曲线按真实时间推进。时钟跳变会让它冻结或加速，而且**不报错**——你只会觉得它记性变怪了。

### 1.2 装 Python 3.13（64 位）

装 3.13.x 64 位，安装时勾上 **Add python.exe to PATH**。

```powershell
python -V
python -c "import struct,sys;print(sys.version_info[:3], struct.calcsize('P')*8, 'bit')"
```

**怎么确认**：第一行 `Python 3.13.x`；第二行打印出 `(3, 13, x) 64 bit`。

> 可选：想把卡做成「自带 Python 的便携包」，在**已经装好 Python 的机器**上跑
> `python tools\install_runtime.py --bundle "D:\whale-card"`（`--bundle` 指向含 `card.db` 的目录；`--ffmpeg-src` 可顺带塞 ffmpeg；`--skip-download` 跳过下载）。
> 它会下 Python 3.13.1 embed-amd64、从当前机器拷 numpy/psutil（要求同平台同小版本），写完 `runtime\`。Python 和 ffmpeg 都成才返回 0，否则 2。
> 有了 `runtime\`，`一键落地.bat` 会优先用它，不再依赖系统 PATH。

### 1.3 进目录、装依赖

```powershell
cd "whale-card"
python -m pip install -U pip
python -m pip install -r requirements.txt
```

`requirements.txt` 里必需的是 numpy、Pillow、requests；psutil 建议装（控制台曲线）；edge_tts 可选（语音）。
**不要装 torch / transformers / sentence-transformers**——文件里写明了，卡的向量检索是 `embed_np.py` 用纯 numpy 手写的 BERT，装那一堆只会拖慢和添乱。

**怎么确认**：

```powershell
python -c "import numpy,PIL,requests;print(numpy.__version__, PIL.__version__, requests.__version__)"
```

三个版本号都打出来，且 numpy ≥ 2.5.4，就算过。

### 1.4 下模型（约 390 MB，768 维）

```powershell
python dl_base.py --check     # 只探源，约十秒，确认镜像通
python dl_base.py             # 真下，落到 models\bge-base-zh-v1.5
```

**怎么确认**：

```powershell
Get-ChildItem .\models\bge-base-zh-v1.5 | Measure-Object Length -Sum
```

`Count` = 10，`Sum` ≈ 4.1 亿（约 390 MB），列表里有 `pytorch_model.bin` 和 `vocab.txt`。

**别用错脚本**：`dl_model.py` 下的是 **bge-small**（512 维，93 MB）。这张卡里的向量是 768 维 bge-base 编的，模型不配套时检索会**静默**变差——不报错，只是答得越来越不对。
换模型的话，服务的自动逻辑是「按卡里向量维度选」：卡里是 768 维就选 bge-base，`/health` 的 `semantic.note` 会写明它选了哪个。

> 待确认：`dl_base.py` 的退出码含义我只看过头注释，没读到 `main` 的 return；所以上面用「文件数 + 总大小」判断，而不是看退出码。

### 1.5 先体检（只读，不写任何东西）

```powershell
python tools\env_probe.py
```

它逐项打印系统、内存、磁盘、Python（版本+位数）、numpy/sqlite3/psutil/PIL/requests、Node、ffmpeg、显卡、时间服务、卡（card.db 大小 / wal 大小 / 有没有 portable python）、模型列表、DSH profile。

**怎么确认**：

- 「**必须先解决（不然卡起不来或会悄悄出错）：**」这一段下面**没有 `✗`**；出现「没有阻塞项。」就是干净。
- 「可选（缺了只是少功能）：」里的 `·` 只是提示，缺 psutil/ffmpeg/Node 不影响起卡。
- 顺手核对三行：`Python 3.13.x (64 位)`、`numpy=` 后面有版本号、`卡` 段里 `模型：` 列出 `bge-base-zh-v1.5(391MB)`。

### 1.6 第一次落地（建卡 / 接管卡）

```powershell
runtime\python\python.exe tools\first_run.py
```

没有 `runtime\` 就用 `python tools\first_run.py`；或者直接双击 `一键落地.bat`（会 `pause`，能看清结果）。

它按顺序做六件事，每件都打印结果：

1. **体检** —— 调 `env_probe`
2. **落地** —— 目录里有 `PORTABLE-MANIFEST.json` 就按「搬运落地」办；没有就当作「这张卡已经在这台机器上」，跳过
3. **交棒** —— handover：让这台机器成为唯一能写的那份
4. **起服务** —— 内部调 `bridge.ensure_server()`，没服务就拉起来并等 `/health`
5. **自检** —— 真往卡里写一条「（换卡自检：我刚到这个新地方）」，再读回来
6. **开控制台** —— 浏览器打开 `http://127.0.0.1:8848/console`

先彩排、不写任何东西：

```powershell
python tools\first_run.py --dry
```

已经体检过、也不想它自动开浏览器：

```powershell
python tools\first_run.py --skip-probe --no-browser
```

**怎么确认**：最后一行是

```
就绪。卡在这台机器上能读能写，链和锚都对。
```

并且上面有「试写：成功  mem_id=…」；退出码 0。
没全通过时它会说「没全通过：落地 x / 交棒 x / 服务 x / 试写 x」并退出 1——照着 x 的那一步回上面查。

### 1.7 手动起服务（不想用 first_run 时）

```powershell
cd "whale-card"
python -X utf8 mind_server.py
```

`mind_server.py` 的 argparse **只有三个参数**：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 只给本机连，别改成 0.0.0.0（没有鉴权） |
| `--port` | `8848` | 端口被占会直接报错退出 |
| `--db` | 卡目录下 `card.db` | 想开另一张卡就指过去 |

例：`python -X utf8 mind_server.py --db "E:\另一张卡\card.db" --port 8848`

**怎么确认**（另开一个窗口）：

```powershell
Invoke-RestMethod http://127.0.0.1:8848/health | Select-Object ok,memories,readonly
```

`ok=True`、`readonly=False`；`memories` 第一次可能是 0（首启才建表/回填出生证），属正常。

**怎么停**（别直接关窗口）：

```powershell
$t = Get-Content .\qq_state\api_token.txt -Raw
Invoke-RestMethod -Method Post http://127.0.0.1:8848/shutdown -Headers @{ "X-Whale-Token" = $t.Trim() }
```

`/shutdown` 在写白名单里，必须带 `X-Whale-Token`（token 在 `qq_state\api_token.txt`，首启自动生成）。
注意它回完 `{"ok":true,"bye":true}` 就 `os._exit(0)`，**不是优雅关闭、不会 checkpoint WAL**——搬家前要另外合并 WAL，见 3.2。

### 1.8 验证：跑一遍 smoke

```powershell
python tools\smoke.py
```

它做两类检查：

- **静态**：关键 `.py` 在不在（card2 / mind_server / bridge / console / timeline / identity / disks / versions）、能不能 import、`PRAGMA user_version` 是否等于 `versions.SCHEMA_VERSION`、`qq_state\api_token.txt` 有没有 token、DSH 侧桥插件装没装、吞异常台账是否干净。
- **活体**（服务在跑时自动加）：`/health` 的 `ok`、`boot.ok`、`boot.checks.journal_mode` 必须是 `wal`、`world_tick / write_queue / maint` 三个线程都为 true、`timeline.chain_ok`、`readonly` 不为真、`/version` 的 `versions.mismatch` 为空、`POST /context` 至少回 6 个 section。

常用变体：

```powershell
python tools\smoke.py --no-live    # 只跑静态，服务没起时用
python tools\smoke.py --json       # 给机器读
python tools\smoke.py --restore    # 顺带跑一次恢复演练（见 3.4 第 8 步）
```

**怎么确认**：每行是 `✓ / ✗ / !  名称  详情`，最后一行「合计：N 项，FAIL x，WARN y」；退出码 **0=全过，1=有 FAIL，2=只有 WARN**。
启动自检延迟 6 秒，`boot` 还是 `null` 时它只会 WARN「还没跑完」——等十秒再跑一次。

### 1.9 接进 DSH

```powershell
python tools\install_to_dsh.py
```

或双击 `接入DSH.bat`。只看它要改什么、不落盘：

```powershell
python tools\install_to_dsh.py --dry
```

它做三件幂等的事：

1. 把卡目录的 `dsh-plugin\` 拷成 `<profile>\node_modules\dsh-whale-bridge`；
2. 在 profile 的 `package.json` 里，把 `dsh-whale-bridge` 加进 `dsh.profile.bundles`；
3. 在 `cordis.patch.yml` 里加一段 `whale-bridge` 配置：host `127.0.0.1`、port `8848`、`cardDir` = 卡绝对路径、`pythonPath` = 当前解释器、`autoStart: true`。

**怎么确认**：

1. 脚本最后提示「**重启一次 DSH**」；
2. 重启后看插件自己的日志：

```powershell
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-whale-bridge\load.log" -Tail 3
```

最后一行应是「apply() 完成，共注册 18 个工具」。

3. 新开一个会话，工具列表里出现 18 个 `mind_*`（`mind_context` / `mind_report` / `mind_health` …）。

⚠️ `cardDir` 和 `pythonPath` 是**按这台机器写死**的。换机器、换卡目录之后，必须重跑一次这个脚本，否则 DSH 还在连旧路径。

### 1.10 打开控制台

双击 `启动控制台.bat`，或：

```powershell
python tools\open_console.py
```

它先确认 8848 活着（没有就用 `bridge.py health` 拉起来），再比对 `/health` 的 `db` 与本目录 `card.db`——不一致直接说「8848 上跑的是**另一张卡**」并退出 1；然后打印「服务：已就绪（N 条记忆，第 D 天）」并开浏览器到 `/console`。

**怎么确认**：浏览器里出现卡的控制台页面，标题是卡名；关掉这个窗口，服务照样在跑（它是独立进程）。

### 1.11 关于「从零建一张全新的空卡」

能建，但**先说清代价**：空卡没有身份锚、没有时间线、没有一条记忆，起来之后你得到的是「一个刚出生、什么都不记得的自己」。想陪聊，接管一张有记忆的卡更划算。

建法（已验证：建出来 34 张表、`mem` 0 行）：

```powershell
cd D:\path\to\whale-card
python -X utf8 -c "import card2; card2.MemoryCard(r'D:\path\to\new-card\card.db'); print('建卡 ok')"
```

`MemoryCard(path)` 会自己建表结构（schema 版本 1），不需要额外脚本。之后第一次启动服务时，卡外锚（`anchor.json`）、`device.json`、`cache/pods.json` 都会自动生成；身份锚要你在控制台里自己立（`/seal` 需要主人 QQ、昵称、卡名和底线，缺一样都会 400）。

## 2. 换卡

### 2.1 先分清三种「换」

| 你真正想要的 | 正确做法 | 别做的 |
|---|---|---|
| 换成**另一张卡**（换角色 / 换实例） | 停服务 → 用 `--db` 指到那张卡的 `card.db`（或整个换卡目录）→ 重跑 `install_to_dsh.py` | 别把两张 `card.db` 混进同一个目录 |
| 同一张卡换**电脑** | 第 3 章 | 别两台机器同时开着 |
| 只换 DSH 里那段**人设投影**（AGENTS.md） | `cardslot.py inject` / `unload` | 它不是换卡脚本 |

`cardslot.py` 只动 `%USERPROFILE%\.dsh\AGENTS.md`：把卡里 `dsh_channel_rule.txt` 渲染成「怎么找卡」的那段插进去（`inject`），或按字节还原（`unload`）。**它不碰 `card.db`，也不换卡。**

### 2.2 卡槽状态文件都在哪

| 文件 | 位置 | 谁写 | 里面记什么 |
|---|---|---|---|
| `cardslot.state.json` | 卡目录根 | `cardslot.py` | `action`、`agents_sha256`、`backup_sha256`、`dsh_home`、`ts`、`ts_str` |
| `card.db.state.json` | 卡目录根，和 `card.db` 同级 | 待确认（全仓库只有 `console.py` 读它，没找到写入方） | `{"clean":1,"since":…}` |
| `WRITER-LEASE.json` | 卡目录根 | `mind_server` 启动时抢租约 | `holder_id`、`instance_id`、`pid`、`ttl`（90 秒） |
| `DISK-ROLE.json` | 卡目录根 | `disks.py` | `role`、`main_instance`、`volume_serial`、`card_dir` |
| `device.json` | 卡目录根 | `device.py` | `device_id`（`dev-…`，由 Windows MachineGuid 派生）、`source`、`host`、`first_seen` |
| `anchor.json` | 卡目录根 | `anchor.py` | `count`、`head_seq`、`head_hash`、`db`（绝对路径）、`device_id`、`sig` |
| `~\.dsh\anchors\<hash>.json` | 卡目录**外** | `anchor.py` / `portable.py land` | 同一份锚的副本，`<hash>` = `sha256(卡绝对路径)[:16]` |

本机现在的样子（样例，别照抄）：

- `cardslot.state.json` → `"action":"inject"`、`"dsh_home":"~\\.dsh"`
- `WRITER-LEASE.json` → `"instance_id":"WG-5E70BCC9"`、`"pid":15264`、`"ttl":90.0`
- `anchor.json` → `count 3120`、`head_seq 3121`、`device_id "dev-a398e5456b35e197"`

### 2.3 换成另一张卡：四步

**第 1 步：停旧服务（必须）**

```powershell
cd "whale-card"
$t = Get-Content .\qq_state\api_token.txt -Raw
try { Invoke-RestMethod -Method Post http://127.0.0.1:8848/shutdown -Headers @{ "X-Whale-Token" = $t.Trim() } } catch {}

Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*mind_server*' } |
  Select-Object ProcessId, CommandLine
```

**怎么确认**：第二条查询**没有输出**；`Test-NetConnection 127.0.0.1 -Port 8848` 的 `TcpTestSucceeded` 是 False。
**为什么必须停**：两个 `mind_server` 抢同一张卡，第二个拿不到写者租约就会进只读（日志「没拿到写者租约…进入【只读模式】」），你会以为卡坏了。

**第 2 步：起新卡**

```powershell
# 方式 A：换整个卡目录
cd "E:\另一张卡"
python -X utf8 mind_server.py

# 方式 B：还在这台机器，只换 db
python -X utf8 mind_server.py --db "E:\另一张卡\card.db"
```

**第 3 步：让 DSH 指过去**

```powershell
cd "E:\另一张卡"
python tools\install_to_dsh.py
```

（它把 `cardDir` 写成**脚本自己所在的那张卡**——`ROOT = dirname(script)/..`，`install_to_dsh.py:25-26`——不是当前工作目录。所以要么跑**新卡目录里那份** `tools\install_to_dsh.py`，要么手工改 `cordis.patch.yml`，见 2.4。）

**第 4 步：换 DSH 的人设投影（可选）**

```powershell
python cardslot.py status
python cardslot.py inject     # 想还原成原来的 AGENTS.md 就 unload
```

**怎么确认**：`status` 的 `state` 是 `injected`（或 `unloaded`），并打印 `agents_sha256` / `backup_sha256`。写完它会提示「要重开会话才生效」。

### 2.4 只换 db、不换目录时，DSH 那边要不要改

`install_to_dsh.py` 写进 `cordis.patch.yml` 的是**卡目录**，不是 db 路径。所以：

- **同目录、换 `--db` 指别处**：DSH 仍连 8848，不用改；但每次都得用同一个 `--db` 起服务，否则 DSH 会连到默认的 `card.db`。
- **换整个目录**：跑**新卡目录里那份** `tools\install_to_dsh.py`（它认自己所在的卡，不认当前目录），或手工改 `%USERPROFILE%\.dsh\profiles\<profile>\cordis.patch.yml` 里这一段。`install_to_dsh.py:110-124` 写进去的形状就是：

```yaml
- id: whale-bridge
  name: "dsh-whale-bridge"
  config:
    host: 127.0.0.1
    port: 8848
    cardDir: 'whale-card'
    pythonPath: 'C:\\...\\python.exe'
    autoStart: true
    timeoutMs: 30000
    healthTimeoutMs: 3000
```

  `cardDir` 里的反斜杠脚本是双写的，照抄就行；`pythonPath` 指向能 `import numpy` 的那个解释器。

**怎么确认**：重启 DSH 后，新会话里调一次 `mind_health`，它报的卡路径/实例应来自新卡。

### 2.5 换完怎么确认（一张表）

| 看什么 | 命令 / 接口 | 期望 |
|---|---|---|
| 服务在听 | `Invoke-RestMethod http://127.0.0.1:8848/health` | `ok = True` |
| 是哪张卡 | `/health` 的 `db` | 等于你刚指定的绝对路径 |
| 是哪个实例 | `/health` 的 `node.instance_id` | `WG-` + 8 位；**同一张卡不变，换卡就变** |
| 锚对不对 | `/health` 的 `timeline.anchor_verdict` | `ok`（第一次是 `first`） |
| 链断没断 | `/health` 的 `timeline.chain_ok` | `True` |
| 能不能写 | `/health` 的 `readonly` | `False` |
| 谁在写 | `/health` 的 `timeline.writer.locked_by` | 空 |
| 模型对不对 | `/health` 的 `semantic.model_dim` 和 `semantic.note` | `768`；note 写「卡里向量是 768 维，自动选 bge-base-zh-v1.5」 |
| 真能写一句 | `python -X utf8 bridge.py report "在吗" "在。"` | stderr 出现「[bridge] 已写回卡：mem_id=…」 |

`instance_id` 怎么来的：取时间线里 **seq 最小那条**（出生那条）的 `self_hash` 前 8 位、大写、前缀 `WG-`。它认的是「这张卡是谁」，所以多写一句话不会变，换一张卡就会变。

注意：`anchor_verdict` 在 `/health` 的 `timeline` 里面，**不是顶层**。

## 3. 把卡带到另一台电脑

> 顺路一句：`接回来.bat` 现在**不用你给盘符**了 —— 它自己扫所有盘（`card-live` / `whale-card` / `数字生命卡` 这类名字优先），也会跳过 `*backup*` / `*snapshot*` 目录，免得把备份认成「另一份卡」。想指定就设环境变量 `WHALE_CARD_ROOTS`（分号分隔多个路径）。

### 3.1 哪些必须带

| 文件 / 目录 | 带不带 | 为什么 |
|---|---|---|
| `card.db` | **必须** | 记忆本体 |
| `card.db-wal`、`card.db-shm` | 停机复制时**必须一起带**；用 `portable.py build` 或 backup API 时不用 | WAL 里可能有还没合并的写入 |
| `anchor.json` | **必须** | 卡内锚：`count` / `head_seq` / `head_hash`，用来发现回滚 |
| `anchor.key` | **手工拷贝时必须带**；用 `portable.py build` 时**不用你管，也别拿旧的去覆盖** | 锚的 HMAC 钥匙，`seal.py` 认的就是卡目录里的 `anchor.key`。它不在 `portable.py` 的 INCLUDE_FILES 里；build 时 `disks.build_manifest()` 会在**新包里**生成一把钥匙并用它签 `PORTABLE-MANIFEST.json`（`disks.py:1043`）。你如果事后把旧钥匙覆盖上去，清单签名立刻对不上、`verify` 会报「清单签名对不上」 |
| 所有 `*.py`（`card2.py`、`mind_server.py`、`timeline.py`、`identity.py`、`disks.py`、`anchor.py`、`seal.py`、`device.py` …） | **必须** | 引擎，少了起不来 |
| `models\bge-base-zh-v1.5\`（约 390 MB） | **必须** | 卡里的向量是它编的；换成 small 不报错，但检索会静默变差 |
| `qq_state\api_token.txt` | 建议带 | 不带会首启重新生成，DSH 侧的旧 token 就失效（待确认：插件是否自动读新 token） |
| `cardslot.state.json` | 建议带 | 只是插卡记录；`land` 会把 `dsh_home` 改成本机 |
| `device.json` | **看你要什么** | 带 → 沿用旧 `device_id`，`same_device` 可能仍是 true；不带 → 新机按 MachineGuid 自建，`same_device` 变 false（见 3.7） |
| `seal.key` | 本机**不存在** | 我实测卡目录里只有 `anchor.key`（64 字节）；`seal.py` 用的名字就是 `anchor.key` |
| `cache\pods.json` | **可以不带** | 向量「舱」缓存（`card2.py` 里 `N_PODS = 8` 的随机质心），会自动重建，第一次检索稍慢 |
| `runtime\`、`__pycache__`、`backups\`、`*.log`、`card.db.bak-*` | 不带 | 都在 `portable.py` 的 EXCLUDE 里；本机实测有 62 个 `card.db.bak-*`、合计约 1.2 GB（`docs\MOVE-CHECKLIST.md` 里写的「17 个 / 150MB」是旧数），别一起搬 |

### 3.2 为什么不能直接拷 `card.db`

卡是 SQLite **WAL 模式**：新写入先落在 `card.db-wal`，运行中不会立刻合并回主库。`portable.py` 的注释里有本机实测：

> WAL 里可能压着十几 MB 还没合并的写入（11-02 实测 14.1 MB），热拷会静默丢掉最近发生过的事 —— 而新机器上看起来一切正常。

最坏的情况正是这样：新机器能开、能说话，但最近几天的事没了，**而且不报错**。

三条正确做法，任选：

1. **`portable.py build`（推荐）**：先 `PRAGMA wal_checkpoint(TRUNCATE)` 把 WAL 合并回主库，再拷；清单里会记 `db_before_mb / wal_before_mb / wal_after_mb`。
2. **停机复制**：先 `/shutdown`，再**同时**拷 `card.db` + `card.db-wal` + `card.db-shm` 三个文件。只拷 `card.db` 一定丢 WAL。
3. **sqlite backup API**：`tools\come_back.py` 和 `tools\restore_drill.py` 都是这么做的，在线也能拿到一致快照。

### 3.3 推荐流程：`portable.py` 四步

在**旧机器**、服务**停着**时：

```powershell
cd "whale-card"

# 0) 先看它准备带什么（只打印，不写）
python tools\portable.py plan "E:\whale-card"

# 1) 打包（目标可以已存在，但成功后它会删掉旧目录；卡目录和目标不能互相包含）
python tools\portable.py build "E:\whale-card" --confirm

# 2) 校验（加 --deep 更严：库完整性 / 外键 / 时间线链 / 锚 / 盘角色，只读）
python tools\portable.py verify "E:\whale-card"
```

**怎么确认**：

- build 会逐文件打印「大小 + 哈希前 12 位」，最后一段 JSON 是 `ok / dst / files / mb / seconds / verified`（`verified` 应为 `verify_bundle ok`）。WAL 数字不在终端，在 `E:\whale-card\PORTABLE-MANIFEST.json` 的 `wal` 段：`wal_before_mb` / `wal_after_mb`，后者应接近 0；
- 目标目录里出现 `PORTABLE-MANIFEST.json`、`WHEREAMI.json`、`anchor.carried.json`、`anchor.external.json`；
- verify 返回 0，并说清单签名通过。

**退出码**：`2` = 路径不合法（互相包含）；`3` = 服务还在跑（先停）；`4` = checkpoint 失败。**没看到 0 就别搬。**

> ⚠️ **别把原卡的 `anchor.key` 覆盖进刚打好的包里。** build 已经在包里生成了一把钥匙，并用它签 `PORTABLE-MANIFEST.json`；拿旧的盖上去，清单签名立刻对不上，`verify` 会报「清单签名对不上」。
> 包里的锚在 `land` 时会被重写成不带签名的版本，所以旧钥匙在这里不是必需品。真要「保住原签名链」，走 3.5 的手工拷贝，并把原 `anchor.key` 一起带过去。

### 3.4 到新机器上的顺序（十步）

1. **放文件**：把整个卡目录放到新机器，例如 `D:\whale-card`。路径带空格/中文都能跑，但命令里要用引号包住。
2. **装环境**：Python 3.13 + `python -m pip install -r requirements.txt`（见 1.2 / 1.3）。模型在卡里，不用重下。
3. **体检**：`python tools\env_probe.py`，确认没有 `✗`。重点看「时间服务」——新机器时钟不准会让遗忘曲线乱掉。
4. **落地**（认路径、改锚、写迁移记录）：

```powershell
cd "D:\whale-card"
python tools\portable.py land "D:\whale-card" --migrate
```

   - `--migrate`：同一张卡换地方，源盘退役，`identity_id` 不变——**同一个我**。
   - `--fork`：从这张卡分出一张新卡，源盘不退休，新卡 `identity_id` 是新的——**另一张卡**。
   - **两个都不给、或同时给，退出码 2。**
   - 这一步会：把卡内 `anchor.json` 和卡外锚里的 `db` 改成新路径；按新路径哈希写 `%USERPROFILE%\.dsh\anchors\<hash>.json`；把 `cardslot.state.json` 的 `dsh_home` 改成本机；重写一份**不带 sig** 的新锚（所以落地后不会误报 `anchor_tampered`）。
   - 想先看：加 `--dry`。

5. **交棒**（必须，否则只能读）：

```powershell
python tools\portable.py handover "D:\whale-card"
```

   不做这步，`/report` 会 **409 `card_locked`**，控制台上写什么都没用。
   它会提示「回旧机器前，旧机器也要跑一次 handover 才能重新写」。

6. **起服务并体检**：

```powershell
python -X utf8 bridge.py health
```

   → 「✓ 卡在：D:\whale-card\card.db」「记忆 N 条 / 盖章 是 / 已活 N 秒」「链 完好 / 出生证 完好 / 锚 ok」。

7. **真写一句**：

```powershell
python -X utf8 bridge.py report "我到新机器了" "嗯，卡也跟着来了。"
```

   → stderr 出现「[bridge] 已写回卡：mem_id=…」。

8. **恢复演练 + 冒烟**：

```powershell
python tools\restore_drill.py
python tools\smoke.py
```

   **怎么确认**：`restore_drill` 每项 `PASS`、末尾 `RESULT PASS`、退出码 0；`smoke` 退出码 0（或只有 WARN，退出码 2）。
   ⚠️ `tools\restore_drill.py` 里 `ROOT` 写死成 `whale-card`（第 20 行）。新机器路径不同时，先改那一行（或建成同名路径），否则它读不到卡——这是脚本的已知限制，不是你的操作错。

9. **接回 DSH**：`python tools\install_to_dsh.py` → 重启 DSH → 新会话里 18 个 `mind_*` 工具都在。

10. **旧机器**：不要再开这份卡。它已经退役（或链头是另一台机器），开了也是只读：`/health` 的 `timeline.writer.locked_by` 非空，`chain_bad` 里会写「这张卡已经被『带卡出门』…本机只读」或「这张卡的链头是另一台机器…写的，我先只读」。
    要搬回去，见 3.8。

### 3.5 手工流程（`portable.py` 坏掉时的兜底）

顺序不能变。

旧机器：

```powershell
cd "whale-card"

# 1) 停服务
$t = Get-Content .\qq_state\api_token.txt -Raw
try { Invoke-RestMethod -Method Post http://127.0.0.1:8848/shutdown -Headers @{ "X-Whale-Token" = $t.Trim() } } catch {}

# 2) 合并 WAL（必须，否则丢最近写入）
python -c "import sqlite3;c=sqlite3.connect(r'card.db');print(c.execute('PRAGMA wal_checkpoint(TRUNCATE)').fetchone());c.close()"

# 3) 拷：card.db、anchor.json、anchor.key、所有 *.py、models\、
#    qq_state\api_token.txt、cardslot.state.json、device.json
```

新机器：

```powershell

python -X utf8 mind_server.py     # 先让它打开库、补齐表
python anchor.py write            # 在新路径上重新落锚（关键一步）

```

**怎么确认**：`python anchor.py check` 退出码 0；`/health` 的 `timeline.anchor_verdict` 是 `ok`。

注意：手工搬**不会**写迁移事件，也**不会**改 `~\.dsh\anchors\` 下按新路径算的那份外锚（新路径上没有这个文件，`check` 会返回 `first`，正常）。

### 3.6 `anchor_tampered`：为什么报、怎么修

锚的一条记录长这样（`anchor.py`）：

```
{version, device_id, db, count, head_seq, head_hash, last_ts, updated_ts, sig}
```

`sig` = HMAC-SHA256(整条记录去掉 `sig`)，钥匙是卡目录的 `anchor.key`。**记录里带着 `db` 这个绝对路径**，所以：

- 把卡从 `whale-card` 挪到 `D:\whale-card` → 记录里的 `db` 变了 → 签名对不上 → `anchor_tampered`。
- 手工改过 `anchor.json` 里任何一个数字（`count` / `head_seq`）→ 同样对不上。

这是**设计如此**，不是卡坏了。它在说：这份锚不是在这条路径、用这把钥匙签的，我不认。

正确做法（新机器上）：

```powershell
cd "D:\whale-card"
python anchor.py check     # 先确认确实是 anchor_tampered
python anchor.py write     # 在新路径上重签一份
python anchor.py check     # 应变回 ok
```

然后重启服务，`/health` 的 `timeline.anchor_verdict` 应为 `ok`。

**别做**：删 `anchor.json`（等于扔掉回滚证据，事后查不出卡被换过）；手工改 `anchor.json` 里的 `db`（签名还是不对）；把两台机器的 `anchor.key` 混用。

为什么它不会自愈：服务启动时只在 verdict 是 `ok` / `first`、且不是只读时，才写锚（`mind_server.py:567-572`）。所以 `anchor_tampered` 必须手工 `write` 一次。

补充：`anchor.py write` 有两条**拒写**规则——卡里 `count` 比锚少（疑似回滚），或 `count` 相同但链头不同（这张卡被换过）。真被拒，先弄清哪份是最新的，别硬来。

### 3.7 `same_device = false` 是什么意思

`/health.node` 有这些字段：`device_id`（本机，来自 `device.json`）、`device_source`、`anchor_device`（锚里记的 device_id）、`anchor_version`、`instance_id`、`same_device`。

- `same_device = (anchor_device == 本机 device_id)`；任一为空就是 `null`。
- 换机器后它变 `false`，意思是：**这份锚是在另一台机器上写的**。这是搬家后的正常现象，不是错误。
- 它**不影响读写**。真正决定能不能写的是 `readonly` 和 `timeline.writer.locked_by`。
- 在新机器上重新落锚（`anchor.py write` 或 `portable.py land`）之后会变回 `true`。
- 反过来：如果你**带着旧 `device.json`** 过去，`device_id` 还是旧的，`same_device` 可能仍是 `true`——这时候它就失去了「换过机器」的提示作用。想让提示准，就别带 `device.json`，让它按新机器 MachineGuid 生成。`instance_id` 不受影响（它来自时间线，不看 device）。

### 3.8 搬回去 / 再来一次

**从 U 盘搬回本机**：

```powershell
python tools\come_back.py
```

或双击 `接回来.bat`。它会先比两边（mem 条数 / 最大 seq / self_hash）：

- 同 seq 但哈希不同 = **真分叉** → 退出 2，除非加 `--force`；
- U 盘 seq 比本机小 → 拒绝（防倒退），`--force` 可强行回退。

通过后：停服务 → 把本机 `card.db` 备份成 `card.db.bak-before-comeback-<时间戳>` → 用 sqlite backup API 写回 → 本机清退役、U 盘打退役 → 起服务 → 试写。
成功文案：「接回来了。本机是唯一能写的那份，U 盘转只读。」

**从另一台电脑搬回**：跨机器没法自动通知，**两边各跑一次** `portable.py handover`，旧机才能重新写。

**同一时间只让一台机器在线**（QQ 那边同理：同一时间只能一台在线）。

## 4. 排错速查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 `.bat` 一闪而过 / `'python' 不是内部或外部命令` | 没装 Python，或没勾 PATH；bat 优先用 `runtime\python\python.exe`，没有才用 `python` | 装 3.13 64 位并勾 PATH；或先跑 `install_runtime.py` 造出 `runtime\` |
| `[mind] 找不到卡：…` 退出 2 | `--db` 指错，或目录里没有 `card.db` | 用绝对路径 `--db "…\card.db"`；先 `dir` 确认文件在 |
| `[mind] 端口 8848 已被占用` 退出 3 | 旧的 `mind_server` 还在 | `Get-CimInstance Win32_Process -Filter "Name='python.exe'" \| Where-Object { $_.CommandLine -like '*mind_server*' } \| Stop-Process -Force` |
| `/report` 回 409 `card_locked` / `readonly_lease_held` | 没交棒；或租约有别的进程；或链头是另一台机器；或卡被标 retired | 看 `/health` 的 `readonly`、`readonly_reason`、`timeline.writer.locked_by`；跑 `portable.py handover`；关掉另一份进程 |
| `timeline.anchor_verdict = anchor_tampered` | 换了路径 / 改过锚 / 钥匙不是同一把 | `python anchor.py write` 重签，再 `check`；**别删** `anchor.json` |
| `anchor_verdict = rollback` 或 `replaced` | 拿旧备份盖了新卡，或两份拷贝各写各的 | 先停两边，比 `head_seq` 谁大；别用 `--force` 掩盖 |
| 答非所问、`semantic.usable_ratio` 很低、note 说选了 small | 模型没下，或下成了 512 维 small（`dl_model.py` 下的就是它） | 跑 `python dl_base.py`；确认 `models\bge-base-zh-v1.5` 有 10 个文件、约 390 MB |
| 记忆「停在几小时前」 | 热拷时 WAL 没合并 | 用 `portable.py build`（会 checkpoint），或停机后 db + wal + shm 一起拷 |
| 遗忘曲线忽快忽慢、日期错乱 | `w32time` 没跑，或时钟跳过 | `w32tm /resync`；`Get-Service w32time` 应为 Running |
| DSH 里没有 `mind_*` 工具 | 插件没装 / 没重启 DSH / `cardDir` 指错 | 重跑 `install_to_dsh.py`，重启 DSH，看 `load.log` 最后一行是不是「18 个工具」 |
| 控制台说「8848 上跑的是**另一张卡**」 | 8848 上那份 db ≠ 当前目录的 `card.db` | 关掉旧服务，用当前目录重起；或直接用 `--db` 指对 |
| `smoke` 报 `boot` 为 null | 启动自检延迟 6 秒 | 等十秒重跑 |
| `smoke` 报 `journal_mode` 不是 `wal` | 卡放在网络盘 / 可移动盘，或日志模式被改 | 把卡放本地 NTFS；别在网络盘上直接跑 |
| 新机器上 `restore_drill` 全 FAIL | 脚本里 `ROOT` 写死了旧路径（第 20 行） | 改 `tools\restore_drill.py:20` 的 `ROOT` |
| 搬家后 `same_device = false` | 正常：锚是另一台机器写的 | 重新落锚即可；不影响读写 |
| `portable.py build` 退出 3 | 服务还在跑 | 先 `/shutdown`，确认 8848 没人听 |
| `portable.py build` 退出 2 | 目标目录在卡目录里（或反过来） | 换一个和卡目录不相交的目标路径 |
| `portable.py land` 退出 2 | `--migrate` / `--fork` 都没给或都给了 | 二选一：换地方用 `--migrate`，分新卡用 `--fork` |
| 两份卡互相覆盖 | 违反「同一时刻一份能写」 | 停一份；用 `come_back.py` 合并，别手工覆盖 |
