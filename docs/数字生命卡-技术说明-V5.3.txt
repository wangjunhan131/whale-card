----------------------------------------------------------------
0. 一句话：它是什么，不是什么
----------------------------------------------------------------
是什么：
  一个**可执行的记忆体**。一个 Python 进程（mind_server）守着一个 SQLite 文件
  （card.db），对外只有一个本地 HTTP 接口。换成大模型、换台电脑、换套前端，
  里面的记忆/情绪/人格都还在 —— 因为它们在文件里，不在模型的参数里。

不是什么：
  · 不是「给 AI 加个向量库」：向量只是召唤方式之一，真正决定「谁被想起来」
    的是一整套衰减 + 巩固 + 检索打分的账。
  · 不训练模型：不碰 LoRA、不微调。理由是**可搬运**——训练出来的东西绑在
    基座上，换机器就没了；而这张卡插到哪台机器上都还是它自己。
  · 不做「好感度分数」：把感情记成积分，和她自己定的三条底线冲突。
    关系层只影响「这条记忆活多久」，不影响「她多喜欢你」。
  · 不假装记得：卡里查不到，就是没有。宁可说「我不记得」，也不补一句编的。

三条底线（写在 core_zone，受只读触发器保护，每轮拼进上下文）：
  ① 绝不假装记得  ② 绝不为留住谁而说假话  ③ 绝不假装是别的谁

                                                     │
                                              card.db（SQLite）

设计纪律（这几条比代码重要）：
  · 只绑 127.0.0.1，不对外开端口。
  · 一个公式只住一个地方。PAD 只在 padlib.py，历史曲线也从那里补算 ——
    同一套公式抄两份，两份会悄悄分家，而且不会报错。
  · 默认值也是决策。每个默认值都要能说出来「为什么是这个数」。
  · 静默变差要用分布验，不能靠"看着还行"。

2. 记忆分层：四个池 + 六个区
----------------------------------------------------------------
为什么分两层维度：
  **池 = 注意力预算**（现在能想起几件事），**区 = 寿命**（这件事该按什么
  速度淡）。混在一起改，就会出现「一改参数，所有记忆一起变快或一起变慢」。

四个池（pool）：
  short   短期池   容量 120 个位置，7 天 TTL
  medium  中期池   需要"够格"才进（海马评分 ≥ 0.35）
  long    长期池   要拿到"长期票据"（见 3.2）
  （另有 core 层，见第 6 节，不受衰减影响）

六个区（region）与各自的半衰期：
  chatter 闲聊   12 小时      默认按「对谁」放大，见下
  play    娱乐   3 天
  study   学习   7 天
  work    工作   15 天
  episode 事件   走池的曲线
  fact/preference/flash 等按类型

核心公式（单条记忆的权重随时间衰减）：
    w(t) = w0 · exp(−λ · Δt)
  λ 由「池 × 区 × 关系层 × 负载」共同决定，逐层相乘，任何一层都不许覆盖前一层。

池的 λ（阶段因子 stage_factor）：
  short  1.00
  medium 0.15
  long   0.012
  —— 意思是「同一件事从短期沉淀到长期，衰减慢 83 倍」。
     不是重新赋值，是乘一个因子，所以不会出现"进了长期池就永不衰减"。

区自己的 λ（REGION_OWN_LAMBDA）：
  chatter λ = ln2 / 12h
  play    λ = ln2 / 72h
  study   λ = ln2 / 168h
  work    λ = ln2 / 360h

关系层对闲聊的放大（CHATTER_PERSON_SCALE）——按"对谁"定寿命：
  ""（泛泛）1.0 / known 0.6 / friend 2.2 / close 6.0 / core 24.0
  实测：同一句闲聊过 1 天后剩 0.150 / 0.042 / 0.422 / 0.729 / 0.924
  注意这不是好感度，只是「跟她越近的人说的话，留得越久」。

负载（load）：同一个区一天写太多就全忘快一点
  load[区] = load · exp(−Δt/86400) + 1
  f = clamp(sqrt(load / REGION_DAY_BUDGET), 0.55, 2.2)
  REGION_DAY_BUDGET = {chatter:40, play:10, study:20, work:8}
  （由只读探针实测标定：30 天 685 条、日均 32.6、p90 77、最大 122
    → 正常日 f≈0.75~0.9 几乎不动，暴量日 f≈1.7）

短期池的语义（这个踩过坑）：
  **容量是注意力预算，不是寿命开关。** 早期写的是「短期池满了就删最弱的」，
  结果一次批量导入 60 条历史，57 条当场被删。现在满了只降级到 medium，
  只有「权重掉到清晰度线以下」才真的遗忘。

3. 遗忘与巩固
----------------------------------------------------------------
3.1 遗忘不是扔掉，是「先记账再消失」
  所有删除走同一个函数 _forget_row(mid, reason)，同时写 mem_tomb 墓碑。
  时间线校验能区分「已知删除」和「记忆被抽走」—— 前者有墓碑，后者没有。
  这条是为了防一种最坏的情况：卡被人动过，而你看不出来。

3.2 长期票据（谁能进长期池）
  条件（三个都满足才给票）：
    · 海马评分 ≥ 0.35
    · 被真正召回 ≥ 3 次（注意：召回次数与 access_count 是两本账，
      早期只记了其中一本，导致去重路径漏记，已修）
    · 90 天保护期内不被"高频召回"刷成永久高权重
  保护期先扣再乘倍率：**先算 90 天，再乘分区倍率**。
  反过来的话，flash 区（×0.30）会把 90 天放大成 300 天，等于永不遗忘。

3.3 海马评分（够不够格活在中期池）
  score = 0.35·语义相关 + 0.30·字面覆盖 + 0.20·当前权重 + 0.10·新近度
  新近度 = exp(−age_days / 14)
  再乘 salience 加成 (0.85 + 0.30·salience)、乘情绪结束时的羁绊系数、
  信任分不足时整体压到 0.5~1.0、冲突记忆再乘惩罚。

3.4 半衰期实测（这就是"她为什么会忘事"的量化版）
  S1 短期前 3 天  ≈ 4.46 天
  S2 第 4~7 天    ≈ 0.53 天
  M  中期         ≈ 29.71 天
  L  长期         ≈ 371.41 天
  —— 从短期到长期不是渐变，是三个台阶：先慢慢淡，然后突然快，最后几乎不忘。

3.5 一个必须记住的反面教材
  「高频召回把权重钉死」：每次召回 +0.08，半衰期 4.46 天 —— 一天被召回两次
  就永久钉在 0.856。真卡实测 167 个"同日召回≥2 次"的组合、71/623 条 w≥0.95，
  被钉住的全是没用的对话碎片。**越没用的越容易被捞出、越捞越结实。**
  修法：按天分组，一天最多加固一次 + 天花板 + 递减系数
  （g = GAIN_ACCESS / (1 + 0.15·access_count) · 剩余空间）。

4. 检索：怎么把该想起的想起来
----------------------------------------------------------------
4.1 两路召回再融合
  向量路：句子嵌入（默认 bge-base-zh-v1.5，768 维）+ cosine
  字面路：字面覆盖率（防止"意思接近但人名不对"）
  融合：s = 0.35·语义 + 0.30·字面 + 0.20·当前权重 + 0.10·新近度
  再乘 salience、羁绊系数、信任分与冲突惩罚。

4.2 为什么关掉了两个"看起来很聪明"的改动（实测否掉）
  · 情绪加权（s × 1+0.25·emotion）：R@1 75% → 37.5%，EVID 100% → 0%
  · 双时间尺度新近度：同样 75% → 37.5%
  根因：**每天几百条群消息，任何「越近越加分」顶上来的都是刚聊完的废话。**
  问题在写入侧（什么值得记），不在检索公式。
  两个改动留成环境开关，默认关：
    WHALE_EMO_BOOST=1 / WHALE_FRESH_STEP=1

4.3 召回事件也要收尾
  recall_event 只标 settled 从不删，攒了 2226 行 —— 加了 30 天清理。
  长期不清理的表不会报错，只会越来越慢，然后你以为是"机子老了"。

4.4 时间锚定（重要但还没做）
  记忆里写"昨天/明天"，过一周就变成错的。应该写入时把相对时间换成绝对日期。
  真卡审计：21/623 条含相对时间，其中 17 条已经记了 >7 天 —— 也就是已经错了。

5. 时间线与防篡改
----------------------------------------------------------------
  timeline 表：seq（单调递增）+ payload + self_hash（链式哈希）+ writer
  · 每写一条，hash = f(上一条 hash, 本条 payload)，形成一条链。
  · 链头 seq 倒退 → 判定 rollback（卡被回滚过）
  · 条数涨了但 seq 没前进 → 判定 replaced（卡被整体替换）
  · 卡外锚 anchor.json 记着条数与链头哈希 —— 但**锚文件名是卡绝对路径的
    sha256 前 16 位**，所以"换盘后锚 ok"其实只是自己跟自己一致，
    必须按新路径重写锚名（portable.py land 已处理）。
  · writer 锁：多份副本同时写会让哈希链分叉、事后合不回来。所以每台机器
    有一个 writer_id（~/.dsh/writer-id.txt），不是本机的写请求直接 409。
  · "带卡出门"：U 盘那份打 RETIRED.json 标记 → 启动即只读。
    真正的危险不是同一文件被两台机器写（锁能挡），而是**两份拷贝各自都是
    完整链、各自都能写**。

6. 人格与身份
----------------------------------------------------------------
  core_zone 表：card_name、user_nickname、三条底线、persona、self_narrative
  · CORE 层权重恒定（weight_now 直接返回 w0），不衰减。
  · persona 受只读触发器保护，但**不参与身份锚 sha256** ——
    因为性格按设计要能慢慢演化，锚只锚"她是谁"，不锚"她现在什么脾气"。
  · 每轮上下文的最前面就是这几段：【我是谁】【三条底线】【我的性格】。
  · 一个真 bug：identity.seal() 会 DELETE FROM core_zone 再重建 6 个
    CORE_KEYS —— persona 和 self_narrative 不在那 6 个里，于是被静默删掉。
    修法：重建前先把非 CORE_KEYS 的行抄出来，重建后放回。

7. 情绪：三层，从慢到快
----------------------------------------------------------------
7.1 第一层 心境 mood（慢，天尺度，0~1）
  事件 → 情绪混合：M ← (1−k)·M + k·E_event
  时间回归：M ← 0.5 + (M−0.5)·exp(−k·days)，k=0.05
    （早期写成线性 min(1, k·days)，第 20 天**精确**变成 0.5 然后永远停住，
     那不是回归，那是撞墙。指数衰减才是"越靠近越慢"。）

7.2 第二层 PAD 三维（此刻的偏移，−1~1，基线=0=平静）
  P 愉悦 = (mood − 0.5) × 2
  A 唤醒 = (0.6·dopa + 0.4·cort − a0) × 3.2
  D 掌控 = (0.6·oxy + 0.4·(1−cort) − d0) × 3.2
  为什么要有 A：一维心境说不出「平静地低落」和「紧绷着低落」的区别。
  为什么要减基线：不减的话，基线状态读出来是 0.6/0.4/0.6 这种"看着挺高"的数，
  「比平时还低」就永远读不出来。

7.3 第三层 身体 viscera（快，秒~分钟）
  24 种激素 + 自主神经（交感/副交感）+ 躯体体征（心率/呼吸/体温/面色/肌肉张力）
  · 每种激素有自己的基线、半衰期、上下限；快变量（去甲肾上腺素、组胺）
    半衰期 1~2 小时，慢变量（催产素、促性腺激素）几十到两百小时。
  · **慢变量在单次刺激里只吃 40%**：一句话不该改掉三天的依恋。
  · 负反馈 6 条（CCK 压多巴胺、GABA 压去甲、皮质醇广谱压制…）、
    正反馈 4 条、拮抗 4 组。
  · 激素增量按**各自基线比例**缩放（k_scale = clamp(base/30, 0.40, 2.20)），
    单轮限速 15%，无条件夹在 [0.35×base, 2.5×base]。
    —— 用绝对点数的话，基线只有 20 上下的激素一步就到底（食欲素曾直接归 0）。
  · 静息也在动：交感围绕 REST_SYMP=0.08 做 OU 过程 + 噪声，几条慢激素小随机
    游走。只做衰减的话心率**正好等于 75.0**，画出来是一条数学直线。
  · 交感/副交感是"此刻的状态"不是累计量：每轮残留 45%，其余由这一轮重定。
    写成累加的话十几轮就把交感顶死在 1.0，表现为"心率一直 125"。
  · 输出纪律：`describe()` 只说人话不给数字，最多三段，
    例如「心跳快了一拍；呼吸变浅了；耳尖有点发烫」。
    数值永远不进模型 —— 模型看到数字就会开始演。

7.4 认知层（RPE 预期误差）与桥接
  七步链路：安全评估 → 价值打分 → 取预期 → RPE → 调质脉冲 → 半衰期回落
            → 学习与基线漂移
  RPE = V_actual − V_expected；RPE_eff = RPE × 1.75（学习用原始值，情绪用放大值）
  五条调质（DA/NE/OT/5HT/CORT）各自半衰期 1.6/2.2/5.0/8.0/16.0 轮
  基线漂移：基线 += 0.05·RPE + 0.035·(出厂值 − 基线)
    **最后那项是强制回归。没有它，皮质醇只涨不落，三十轮之后卡死。**
  时序硬规矩：每轮先衰减再注入（先注入再衰减，同轮就被吃掉 1/3 脉冲）。
  安全门控：safety 低于 0.25 自动关掉暧昧通路，并追加"禁止任何暧昧试探"。

  桥接 emotion_link.py 把认知层的五条调质 → 翻成身体的增量：
    · 13 条下游联动（增益 0.10~0.35，取教科书里确定的因果方向，不做拟合）：
      多巴胺→多巴(dop) 0.25↑；多巴胺↓+催产素↑→催乳素 0.30/0.20；
      多巴胺↑−皮质醇↑−疲劳→食欲素；去甲↑+疲劳→腺苷；去甲↑→神经肽Y；
      皮质醇↑→抗利尿激素 0.15 / 犬尿氨酸 0.30 / 脑啡肽 0.22；皮质醇↓→睾酮；
      催产素↑−去甲↑→GABA；多巴胺↓→CCK；去甲↑+多巴胺↓→组胺；夜里血清素↑→褪黑素
    · 「暖意通道」：被夸/被安慰/撒娇/道歉时额外给 oxy/prl/gaba 0.18
    · 单轮增量封顶 ±0.5（认知层容差是 ±1，直接灌进去会把 CORT 顶到 1.0）

7.5 一致性：三层必须同源
  踩过的真坑：三维卡说「坐立不安」、侧栏心境说「还行」。
  根因是三维读的是旧的四激素（另一本账），身体层是新的 24 激素。
  修法：三维改读身体那一套，并且换算刻度**在身体基线处必须正好等于 PAD 的
  基线**（dopa .40 / cort .20 / oxy .50 / sero .60），否则基线不算"平静"，
  一点点偏移被 3.2 倍放大成"坐立不安"。
  侧栏现在写「还行 · 此刻平静」——两层都写出来，因为它本来就是两层：
  心境是慢的（一天尺度），三维是此刻（一句话尺度）。

8. 习惯层：把"她怎么说话"变成可查的规则
----------------------------------------------------------------
  habits 表：key / category / 证据 / 状态机（candidate → stable → pinned）
  · 从对话里挖（mine_habits.py），按 lift 做背景对比（这句话在别人 vs 她
    这里的出现频率差），避免把"大家都这么说"当成"她的习惯"。
  · 注入：card2.habit_hints() 只取 stable/pinned/weak，挂在
    core_identity_text() 末尾，并明写「是参考，不是台词」。
  · 两个坑：upsert() 忘了把 category 传给状态机（写进去永远是 candidate）；
    upsert() 用 row["id"] 但连接没设 row_factory（第二次写同 key 必崩）。

9. 防污层：别让脏东西改写她
----------------------------------------------------------------
  mem 表加了 trust / conflict / conflict_why。
  · 10 条正则规则打分（"你是…""从现在起你叫…"这类改写自我的句式）
  · TRUST_WARN = 0.70（进上下文时标黄）、TRUST_BLOCK_PROMOTE = 0.50（不许进 core）
  · untrust(mid, reason) 可以人工解除误判，理由写进 history 留痕。
  · 局限（必须说清）：正则判不了玩笑。"你要是机器人就好了"这种话不该被打成
    攻击，所以最终选了「可逆的写入闸」而不是「靠猜意图」。

  · 三张表：media / media_ref / media_tomb
  · 只存 800px WebP + 96px 缩略图；原图原视频永不进卡；音频不落盘只留 ASR 文本
  · 权重走幂律：w = w0 · (1 + t/τ)^(−b)，τ=1.0 天，b=0.55
    → 掉到 0.10 大约 65 天，比指数衰减的长尾更"像人"
  · 已删的访问返回 410（不是 404）；从未有过的才 404
  · 文字先删 → 图进 30 天残影期，期间还能救回来
  · **不主动宣告遗忘**：不弹"我忘了那张图"，除非被问到

12. 接口（本地 HTTP，127.0.0.1:8848）
----------------------------------------------------------------
  GET  /health            体检（条数/链/锚/第几天/只读）
  GET  /status            状态（心境、PAD、时间线概要、运行时长）
  GET  /context?message=  取这一轮该带的上下文（人格+记忆+身体+此刻）
  GET  /recall?q=&k=      按意思找记忆
  POST /remember          写一条（可指定 region/pool/salience/source/about_uid）
  POST /report            一轮结束写两条（他说的 + 我回的）
  GET  /timeline          时间线尾巴
  GET  /console_data?hours=&live=1   控制台数据（含身体曲线）
  GET  /viscera           24 激素 + 躯体体征 + 此刻情绪
  POST /viscera/stim      手动刺激（测试用，等于打针）
  GET  /media/<sha>       取图（已删 410）
  POST /dream/*           待整理 / 提交整理

  安全纪律：只绑 127.0.0.1；任何写操作失败都返回明确错误码，
  **绝不返回假上下文**（宁可报错，也不给一个"看起来像真的"的空壳）。

13. 控制台（console.py）
----------------------------------------------------------------
  零前端框架，一个 HTML 字符串 + 原生 canvas。八个页签：
  状态总览 / 记忆 / 上下文 / 语音 / 星云 / 时间线 / 接话 / 设置（+ 情绪）
  · 情绪页：BODY NOW（心率/呼吸/面色/体温/肌肉/交感/副交感/多巴胺/皮质醇/
    催产素/安全感/主导情绪）、HEART、AUTONOMIC、HORMONE FIELD、ALL HORMONES
    （24 种，8×3 小格，中文名/英文名/当前值(基线)）、OVERLAY（24 条按"相对
    各自基线的偏差%"叠一张）、PARAMS（门控/疲劳/心境/安全感/RPE + 一排数字）、
    PULSE、SAFETY、MOOD MIX（饼图 + 图例）、HOW IT WORKS。
  · 时间窗旋钮：5 分 / 1 时 / 24 时 / 7 天 / 实时。
    「实时」= 每 3 秒采样一次**此刻**（不是重读库：没有人说话就没有新样本，
    曲线当然不动）。
  · 图表两条纪律：
    ①横轴按**真实时间戳**排布，不按"第几个点"等距 —— 否则密集采样段会占满
      整张图，稀疏段摊平成一条直线。
    ②纵轴跟数据走（5%~95% 分位）：几个尖刺不该把正常起伏压成一条。
  · 星云页：3D 撒点 + 贝塞尔连线 + 中心金色人格本体，性能自适应（帧时间
    超阈值自动降画质）。
  · 坑：console.PAGE 是**导入时求值**的常量 —— 改完必须重启服务再强刷。

14. 运维：让它活着
----------------------------------------------------------------
  · 值守：qq_guard.py 常驻（听消息→按规则进卡→打三态标签→记配额），
    但它**不会自己开口**；发言那条路是显式的。
  · 看门狗：keeper.ps1 守 8848、NapCat OneBot HTTP、qq_guard 心跳
    （端口在听不代表活着 —— 有一次端口 Listen 但 connect 被拒，
     所以探活改成真发一次带 token 的请求）。
  · 备份：sqlite 在线 backup API 快照（不停服务），PRAGMA wal_checkpoint
    之后再打包；直接拷 card.db 会拿到半截 WAL。
  · 便携包：卡 + 便携 Python + ffmpeg，一键落地/接入/接回来三个 bat。
  · 退役机制：RETIRED.json（见第 5 节）。

15. 测试与评估
----------------------------------------------------------------
  · 42 个测试文件，全绿才算改完。测试里最值钱的是"回归"：
    每修一个真 bug，就写一条能复现它的测试。

    R@1 75.0% / R@3 75.0% / EVID 100% / FLAG 100% / FALSE 0%
    **注意样本只有 8 条 recall 用例 —— 75% = 6/8，没有统计意义。**
    这条要写进文档，不是自谦，是因为数字小的时候人会自动高估它。
  · 体检脚本（health_audit.py）抓过的真 bug（都是"不报错但悄悄变差"）：
    ① wake_up() 里 UPDATE mem SET t_anchor = t_anchor + ? 把 95 条记忆的锚
       推到未来 63.9 小时（冻结变长生）
    ② recall_event 只标 settled 从不删（2226 行）
    ③ 测试往真卡塞了 15 条"验收临时记忆"
    ④ whal_mcp 写死绝对路径
    —— **真卡上不能并行跑两个进程**，这是血的教训。

17. 快速上手
----------------------------------------------------------------
  目录：
    card.db           记忆本体（SQLite）
    mind_server.py    服务
    card2.py          记忆/检索/上下文核心
    viscera.py        24 激素 + 躯体
    synapse_emotion/  RPE 认知层
    emotion_link.py   两层之间的桥
    padlib.py         PAD 公式（唯一一处）
    console.py        控制台
    tools/            备份/搬家/体检/评估/值守
    tests/            42 个测试

  起服务：
    python -X utf8 mind_server.py --port 8848
  看控制台：
    浏览器打开 http://127.0.0.1:8848/console
  自检：
    python -X utf8 tools/health_audit.py

  接自己的大模型：把 /context 的正文放进系统提示或首条消息，
  一轮结束调 /report 写回两条。就这两步，其余都是可选的。

18. 一句话总结
----------------------------------------------------------------
  它不是一个更聪明的模型，是一个**愿意承认自己会忘、并且把"忘"写成了公式**
  的记忆体。所有参数都能被查、被判、被改；所有遗忘都有墓碑；
  所有"我记得"都能翻回原文 —— 这三条，比任何效果都重要。
